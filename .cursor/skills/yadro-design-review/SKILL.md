# Дизайн-ревью Ядра

Внешние generic design-skills не подключаем: они тянут чужую палитру и ломают планшетный UX. Источник правды — только свой канон:

| Что | Где |
|-----|-----|
| Канон бренда, роли, critic §9, driving prompt (Приложение A) | `docs/BRAND_SYSTEM.md` |
| Токены (цвета, радиусы, glass, `--space`) | `src/styles/tokens.css` |
| Правила UI (touch, иконка вместо текста, запреты) | `.cursor/rules/fitness-diary-ui.mdc` |
| Базовые кирпичи `.card`, `.btn`, `.btn-primary`, `.btn-icon-square`, `.btn-touch` | `src/index.css` |
| Empty / loading одного класса, `.os-enter` | `src/styles/os-polish.css` |
| Стили зоны | `src/styles/<зона>.css` |

## Порядок работы

```
- [ ] 1. Скоуп: какой экран/роль, что болит (не «всё приложение»)
- [ ] 2. Код: компонент + его `styles/<зона>.css`, какие токены/кирпичи уже есть
- [ ] 3. Визуальный аудит в браузере (скриншоты)
- [ ] 4. Второе мнение Grok (по желанию / на крупных экранах)
- [ ] 5. Сводка находок → вердикт → только потом правки
- [ ] 6. Правки через токены + повторные скриншоты «до/после»
- [ ] 7. `npm run lint`; если задет критический путь — verify по ship
```

### 3. Визуальный аудит в браузере

1. `npm run dev` (порт 5173; `/api`, `/auth/v1`, `/rest/v1` проксируются на прод; нужен `.env.development.local` с `VITE_SUPABASE_URL=http://127.0.0.1:5173`). Вход — **только владелец сам** вводит логин во вкладке; агент пароли не спрашивает и не вводит.
2. Браузер `cursor-ide-browser`: `browser_navigate` → `browser_lock` → действия → `browser_lock unlock`.
3. Размер окна по роли (через `browser_cdp` `Emulation.setDeviceMetricsOverride`). На планшете работает **только тренер**:
   - тренер — планшет, альбом `1180×820` и портрет `820×1180`;
   - менеджер и админ — только монитор `1440×900` (планшетные размеры для них не проверять).
4. На каждом экране: `browser_take_screenshot`. Для экранов тренера — замер touch-зон через `Runtime.evaluate` (всё кликабельное < 44px — в находки); для менеджера/админа важнее плотность цифр и читаемость, а не крупные тапы.
5. Скриншоты показывать пользователю в ответе картинкой.

Ничего не сохранять, не завершать тренировки и не нажимать «удалить» на проде — только просмотр.

### 4. Второе мнение Grok

Запустить субагента `Task` (`subagent_type: generalPurpose`, `readonly: true`, модель — последняя доступная Grok) с промптом:

```text
Ты — дизайн-директор продукта Ядро. Прочитай docs/BRAND_SYSTEM.md (особенно §5, §7, §9 и Приложение A),
src/styles/tokens.css и .cursor/rules/fitness-diary-ui.mdc. Затем разбери экран: <компонент + css>.
Ничего не меняй в файлах. Верни: A плюсы, B минусы, C ответы на critic §9 (11 пунктов),
топ-5 правок с путём к файлу и конкретным CSS/JSX, вердикт Делаем/Упростить/Отложить/Не делаем.
Запреты: сырые hex, violet/indigo, кнопки <44px, glow-казино, смена смысла фильтров/цифр, светлая тема.
```

Советы Grok не принимать на веру: отсеять всё, что противоречит канону, ломает touch/офлайн или трогает sync.

## Формат итога

```markdown
**Экран:** … · **Роль:** тренер / менеджер / админ
![скриншот](путь)

**Находки** (🔴 мешает работе · 🟡 портит вид · 🟢 мелочь)
- 🔴 … — файл, что поменять

**Critic §9:** провалены пункты … (остальные ок)
**Grok:** с чем согласен / что отсеял и почему
**Вердикт:** Делаем / Упростить / Отложить / Не делаем
```

## Жёсткие рамки при правках

- Только токены (`var(--accent)`, `--radius*`, `--space`), без сырых hex; accent — роли, не модуля.
- Экраны тренера (планшет): touch ≥44px (`btn-touch`). Менеджер/админ (монитор): плотнее, но без мелких нечитаемых цифр. Иконка + русский `title`/`aria-label` вместо лишнего текста.
- Один главный CTA на экран; glow — только CTA / focus / марка.
- Новый блок — `src/styles/<зона>.css` + `@import` в `index.css`, не в монолит.
- Не менять смысл фильтров/счётчиков/воронки, не трогать sync, абонемент, завершение тренировки.
- Продукт — «Ядро» из `productBrand.js`; клуб (FIT-CITY) — не имя продукта.
