# Уровень инженерии Ядра (кратко)

**Актуально:** 2026-11-17. Не roadmap фич — оценка **как написан продукт**. Политика кода: `.cursor/rules/fitness-diary-architecture.mdc`, `fitness-diary-adult-app.mdc`.

## Где мы

| Шкала | Оценка |
|-------|--------|
| Слои (UI / lib / API / БД) | ✅ взрослые |
| Офлайн + Sync | ✅ ядро продукта |
| Auth / роли на сервере | ✅ |
| Verify на ветвлениях | ✅ (не всё покрыто) |
| Автотесты экрана (`qa:screens`) | ✅ узко на критический путь |

| Приложение клиента `/me` | ✅ v1 |
| Per-club настройки (Мои Звонки) | ✅; касса — ⏸ |
| Ширина домена как FitBase | 🟡 уже, не цель копировать всё |
| Правда оплат в Ядре (L3) | ⏸ очередь PATH #6 — код не стартовали |
| God-файлы | 🟡 режем при касании |

**Итог:** прикладная инженерия **зала + CRM-операционки** — взрослая (выше типичной «формы в 1С»). До зрелой **club-OS целиком** не хватает прежде всего **правды денег** в продукте и дожима периметра по команде (#3: 2FA / повторный вход клиента). Цель — свой контур, не копия FitBase.

Ориентир цифрами (не метрика KPI): зал/офлайн/процесс ~7–8/10; продукт как полная ОС с оплатами вместо 1С ~5–6/10.

## Не путать роли в коде и UI

| Структура | role | Маршрут |
|-----------|------|---------|
| Тренеры | `trainer` | `/trainer` |
| Менеджеры | `sales_manager` | `/sales` |
| Управляющие | `supervisor` | `/club` |

`list-trainers` без `role` = только тренеры. См. [CLUB_SUPERVISOR.md](./CLUB_SUPERVISOR.md), [DATA_MODEL.md](./DATA_MODEL.md).
