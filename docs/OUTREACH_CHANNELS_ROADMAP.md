# Каналы связи с клиентами — направление развития

**Статус:** Max у тренера — ✅ в продукте; SMS клуба через «Мои Звонки» — ✅ MVP (одно SMS из админки). Зафиксировано 2026-07.  
**Не путать с:** доступом в приложение (логин/пароль) — это отдельный контур.  
**Настройка SMS:** [MOIZVONKI_SETUP.md](./MOIZVONKI_SETUP.md).

## Принцип: комбинированная модель

| Роль | Канал | Смысл |
|------|--------|--------|
| **Тренер** (планшет) | **Max** — личный чат / ссылка на чат | Уже в продукте: фильтры, шаблоны, очередь, `max_chat_url` |
| **Админ / менеджер** | **SMS «от клуба»** через **Мои Звонки** (API) | Клубный номер/телефон, массовые и «официальные» касания |
| WhatsApp Business | низкий приоритет (РФ: Max важнее) | Не планировать, пока нет явного спроса |

Деньги за SMS/АТС — вторичны относительно ценности канала; решать при подключении провайдера.

## Уже сделано (SMS клуба)

- Одно SMS из админки → Клиенты, лист подтверждения, Мои Звонки  
- **Отдельные шаблоны** `club_sms_templates` (тон клуба), не шаблоны Max тренера  
- **Облачный журнал** `club_sms_log` + отметки на всех устройствах клуба; UI «Журнал SMS» в Max и SMS  
- Настройка: Структура → Max и SMS  

## Уже сделано (тренер + Max)

- Сценарии: ДР / истекает / закончился / давно не был  
- Кнопка Max, прогресс, «следующий», шаблоны в Структуре  
- Поле ссылки на чат → прямое открытие (универсальная идея «ссылка на чат», реализация пока Max)

## Связано: сегмент продажи НК / ДК / УК

Правила в коде: `src/lib/admin/salesClientSegmentCore.js` + `scripts/verify-sales-client-segment.mjs`.

| Сегмент | Правило (как фильтры тренера) |
|---------|---------|
| **ДК** | абонемент **действует** |
| **УК1** (горячий) | 0…13 дн. после конца («закончился») |
| **УК2** (холодный) | ≥ 14 дн. после конца (продажа-возврат; в UI «давно не был» — окно **14–60** дн.) |
| **НК** | иначе, до продажи **не было ни одной** тренировки |

В отчёте с одним полем `profit_uk` обе УК пока складываются в **УК** (`saleSegmentToProfitBucket`).

**Старт:** ядро + verify ✅.  
**Дальше (проекция цели):** при выдаче абонемента — подсказка суммы → **факт оплаты в Оси** ([PAYMENTS_DOMAIN.md](./PAYMENTS_DOMAIN.md)) → день/отчёт. Импорт из 1С по клиенту — только **запасной мост**, не целевой путь денег.

## Дальше (по приоритету)

1. **Дожать Max-очередь** — «старт кампании» на фильтре (N клиентов по одному: копировать → Max → следующий), без blast API.  
2. **Мои Звонки → SMS** — ✅ MVP: одно SMS из админки (Клиенты), шаблон outreach / `expiring`. Env: `MOIZVONKI_*`. См. [MOIZVONKI_SETUP.md](./MOIZVONKI_SETUP.md).  
   - Далее: очередь по фильтру (не blast), webhook журнала  
   - SMS уходит с привязанного Android клуба  
3. **Опционально:** клик «Позвонить» из карточки через API Мои Звонки (`calls.make_call`).  
4. Закладка на масштаб: мыслить «ссылка на чат» / «club outbound», не только бренд Max в модели данных — когда снова трогаем поля.

## Явно не делать без отдельного решения

- Смешивать кнопку Max на планшете и SMS клуба в одном тапе  
- «Одна кнопка = 50 SMS/Max сами улетели» без API провайдера и согласий  
- Тянуть FIT-CITY в Bitrix/amo только ради SMS  
- Своя АТС «с нуля» вместо Мои Звонки / агрегатора  

## Продажа (одна фраза)

Не «мы SMS-шлюз», а: **личный контур тренера (Max) + клубный контур менеджера (SMS/звонок с рабочего телефона)** — удержание клиентов без хаоса в Excel.
