# Архив клиентов — план

## Решения (согласовано)

| Тема | Решение |
|------|---------|
| Список сейчас | ~30–40 активных; за 5 лет до ~200+ в базе |
| Фаза A (сейчас) | Пагинация списка тренера + индексы в workspace snapshot |
| Кто архивирует | Тренер — своих; админ — всех клиентов клуба |
| Архивный клиент | Карточка **только просмотр**; тренировки, абонементы, правки — **после «Вернуть»** |
| Удаление | Кнопка **«Удалить»** остаётся (безвозвратно) |
| Админ, фаза A | Пагинация/индексы — вместе с архивом (фаза B), т.к. сейчас объём небольшой |

## Статистика и «Не активные» (рекомендация)

**Оперативные списки** (вкладка «Клиенты», фильтры, карточка «Не активные» на дашборде):

- Учитываются только клиенты с `archived_at IS NULL`.
- Архивный клиент **не** попадает в «Не активные» — он сознательно убран из работы.

**История за прошлые периоды** (завершённые тренировки в мае 2024, годовой график, журнал за месяц):

- Считаются **факты в том периоде** (тренировки, абонементы), даже если клиент позже ушёл в архив.
- Иначе цифры за прошлые месяцы «поплывут» после архивации.

**Итог:** архив = не в ежедневной работе; прошлая статистика клуба не пересчитывается задним числом.

## Фаза B — ручной архив (следующий релиз)

1. Миграция: `clients.archived_at TIMESTAMPTZ NULL`, индекс `(club_id, archived_at)`.
2. Sync: поле в push/pull (`clients` уже в очереди).
3. `loadTrainerWorkspaceSnapshot`: по умолчанию без архивных; отдельный запрос для вкладки «Архив».
4. UI тренера и админа: вкладки **Активные** | **Архив**; действия «В архив» / «Вернуть»; read-only карточка в архиве.
5. Агрегация «Не активные»: исключить `archived_at IS NOT NULL` в `clubStatsAgg` / `trainerPeriodStats` для **текущего** среза.

## Фаза C — при >5k клиентов клуба

Pull без архивных по умолчанию; подгрузка архива при открытии вкладки. См. `docs/DATA_VOLUME.md`.
