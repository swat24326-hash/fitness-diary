# Дневник калорий клиента (аналог FatSecret)

**Актуально:** 2026-11-21  
**Статус:** 🚀 выкатка — флаг клуба; **Еда** = День / Отчёты / (Рацион у ПЗ) / Ещё; приёмы по кнопке + из рациона; вечерний список тренера. FoodBase — позже.  
**Связано:** [CLIENT_APP.md](./CLIENT_APP.md) столп «Расти», [NUTRITION_DIARY.md](./NUTRITION_DIARY.md) (отметки по рациону тренера — другой контур).

## Зачем

Между тренировками клиенту нечего делать каждый день в приложении клуба → уходит в чужой трекер еды. Свой дневник калорий держит привычку в том же значке. Тренер вечером видит факт без «отправки отчёта» клиентом.

## Кто что видит (ПЗ / АЗ / ТЗ)

| Клиент | Нижние вкладки при флаге | Вкладки внутри Еды | Цель ккал/БЖУ | «В дневник» |
|--------|--------------------------|--------------------|---------------|-------------|
| **ПЗ** (есть «От тренера») | Главная · Тренировки · **Еда** · От тренера · Сообщения | День · Отчёты · **Рацион** · Ещё | Из рациона; иначе **свои** (Ещё → Мои цели) или дефолты | Да, на вкладке Рацион |
| **АЗ / ТЗ** (нет «От тренера») | Главная · Тренировки · **Еда** · Сообщения | День · Отчёты · Ещё | **Свои** цели (Ещё → Мои цели) или дефолты 2000 ккал | Нет (рациона от тренера нет) |

При включённом дневнике у ПЗ пункт **Питание** убирается из «От тренера» (остаётся только **Задание**); `/me/nutrition` → `/me/food-diary?tab=ration`.

## Вкл / выкл по клубам

| Что | Где |
|-----|-----|
| Поле | `clubs.food_diary_enabled` (`boolean`, **default false**) |
| Миграция | `supabase/migrations/20261121120000_clubs_food_diary_enabled.sql` |
| Админ | Организация → список клубов → переключатель «Дневник калорий (клиент)» |
| Клиент | `/api/client-me` → `club.food_diary_enabled`; плитка на главной, вкладка **Еда** и `/me/food-diary` только при `true` |
| DEV | `/me/home-preview` → `/me/food-diary-preview` (превью с вкладкой Рацион) |
| Логика | `src/lib/client/foodDiaryClubCore.js`, verify `verify-food-diary-club.mjs` |

При выключении записи **не удаляем** — скрываем UI; API отвечает 403.

## День и записи

| Что | Где |
|-----|-----|
| Таблица | `client_food_diary_entries` — миграции `20261121130000_…` + `20261121140000_…_extras.sql` |
| API | POST `/api/client-me`: `food-diary-day` / `upsert` / `delete` / `search` / `barcode` / `frequent` / `copy` / `water` / `water-set` / `week` / `from-plan` / **`targets`** / **`targets-set`** |
| Приёмы | 4 базы (завтрак…перекус) + **`extra_1` / `extra_2`** (Перекус 2/3); на дне **не** все слоты сразу — кнопка **«Добавить приём пищи»**; «+» в шапке приёма — продукт. Миграция `20261121170000_…meal_extra.sql` |
| Экран | `/me/food-diary` — см. таблицу ПЗ/АЗ выше; «+» у приёма — шторка: Поиск · Часто · Вручную; штрихкод **только сканом** |
| Цели | приоритет: рацион → свои (`client_food_diary_targets`) → дефолты; форма на вкладке **Ещё** |
| Миграция целей | `supabase/migrations/20261121160000_client_food_diary_targets.sql` |
| «В дневник» | `foodDiaryFromPlanCore` + `food-diary-from-plan`; 5 приёмов рациона → разные слоты (без схлопывания); после записи приёмы **сами** появляются на дне (по записям) |
| Вода | `client_food_diary_water` |
| Verify | `verify-food-diary-{club,day,summary,catalog,habits,vs-plan}.mjs` |

## Тренер

| Что | Где |
|-----|-----|
| API день | GET `/api/admin-data?action=food-diary-client&client_id=&date=` |
| API список | GET `/api/admin-data?action=food-diary-roster&date=` — свои клиенты клуба с дневником; факт/цель/статус без блюд |
| UI список | `/trainer/nutrition` — плитка на главной + пункт меню; чипы Все / В цели / Мимо / Пусто; тап → карточка `?tab=nutrition` |
| UI карточка | `ClientFoodDiaryTrainerGlance` на экране рациона |
| Офлайн | список только online (понятная ошибка на русском) |

## Не путать

- **Рацион от тренера** (`client_plans`, вкладка Рацион в Еде у ПЗ) — план «что есть».
- **Дневник калорий** (`/me/food-diary`) — факт «что съел» + КБЖУ.
- **NUTRITION_DIARY** — отметки «съел по плану» без свободного ввода еды.
