# Дневник питания клиента — ТЗ (фаза 9)

**Статус:** 📋 ТЗ (код ещё не пишем).  
**Связано:** [PRODUCT_MODULES.md](./PRODUCT_MODULES.md), фазы рациона в плане «Питание блюдами».

## Зачем

Тренер выдал рацион в приложение. Клиент ест — или нет. Без отметок тренер гадает; с отчётом можно мягко скорректировать порции и акценты.

## Решение (открытые вопросы — зафиксировать до кода)

| Вопрос | Предложение MVP |
|--------|-----------------|
| Что отмечает клиент? | Только «съел по плану» / «частично» / «не ел» на приём — **без** свободного ввода граммов |
| Свободный ввод еды? | ⏸ backlog (FatSecret / свой поиск) |
| Частота отчёта тренеру | Сводка за 7 дней во вкладке клиента у тренера; push — только если 3+ дня подряд «не ел» (настраиваемо) |
| Офлайн | Отметки в localStorage / IDB → flush в `client_plan_diary` при online |
| Связь с рационом | Строка дневника ссылается на `client_plans.id` + `meal.label` + дата |

## Сущности (черновик)

- `nutrition_diary_entries`: `id`, `client_id`, `club_id`, `plan_id`, `entry_date`, `meal_key`, `status` (`eaten`\|`partial`\|`skipped`), `note` (≤200), `created_at`
- Push allowlist + RLS как у других client-owned таблиц
- API: тонкий `admin-data` / client portal action — не новый Vercel function без нужды

## Экраны

1. Клиент `/me/nutrition`: под каждым приёмом три кнопки статуса за сегодня.
2. Тренер: в карточке «Питание» блок «Как ест» — календарь 7 дней, % съеденного.

## Не делаем в MVP

- Штрафы лояльности за «не ел»
- Фото еды
- Авто-пересчёт рациона по дневнику

## Готово к коду, когда

Владелец подтвердил таблицу статусов и что свободный ввод не нужен в первой версии.
