## Роли и зоны

| Роль | Клуб | Ежедневный отчёт | Расход (одна сумма) | План / сводки | Прочее |
|------|------|------------------|---------------------|---------------|--------|
| **Менеджер по продажам** | один свой | ✅ заполняет, правит прошлые дни | ❌ **не видит** | сосуд + свой клуб | **только зона отчёта** |
| **Управляющий** | один свой | 👁 просмотр отчётов | ✅ параметры + расход | свой клуб + **итоги** | **зона финансов** на той же странице |

**Менеджер по продажам:** один на клуб.  
**Ежедневный отчёт:** один на **клуб / день**.

## Модуль 1 — Ежедневный отчёт отдела продаж

### Поля дня

| Поле | Код | Тип | Описание |
|------|-----|-----|----------|
| Дата | `report_date` | date | Календарный день |
| Клуб | `club_id` | uuid | UNIQUE вместе с датой |
| Прибыль **НК** | `profit_nk` | ₽ | Заработок за день по **новым** клиентам |
| Прибыль **ДК** | `profit_dk` | ₽ | По **действующим** |
| Прибыль **УК** | `profit_uk` | ₽ | По **ушедшим** |
| **Итого за день** | `profit_day` | ₽ | **Считает сайт:** `profit_nk + profit_dk + profit_uk` (не вводится отдельно) |
| ПНК | `pnk_total` | шт. | **Одно число** — потенциальные новые клиенты (**без** ПЗ/ТЗ/АЗ) |
| Тренировок проведено | `trainings_count` | шт. | **По всему клубу за день**, вводит **менеджер вручную** |

**Тренировки:** не тянем из планшетов тренеров — не у всех есть устройства. Отдельное поле в отчёте; позже можно **подсказку** из FIT-CITY (readonly), но **источник v1 — ручной ввод менеджера**.

### Матрица 3×3 — только **количества** (целые ≥ 0)

**Без рублей**, без других единиц — только число в ячейке.

| | **НК** (новый) | **ДК** (действующий) | **УК** (ушедший) |
|---|:---:|:---:|:---:|
| **ПЗ** (персональный зал) | `pz_nk` | `pz_dk` | `pz_uk` |
| **ТЗ** (тренажёрный зал) | `tz_nk` | `tz_dk` | `tz_uk` |
| **АЗ** (аэробный зал) | `az_nk` | `az_dk` | `az_uk` |

### Правка прошлых дней

✅ **Админ** и **менеджер по продажам** (когда роль появится) — **без ограничения по давности** на v1 (при необходимости журнал изменений — позже).

### Связь со статистикой FIT-CITY

Отчёт продаж — **отдельный** ручной ввод. Не подменяет `memberships` / «Не активные».  
`trainings_count` **не равен** автоматически числу `trainings` в облаке, пока не у всех тренеров планшеты.

## Одна страница — две зоны (видимость по роли)

**URL:** `/admin/sales?club=<id>` — **один экран** для всех ролей.  
Состав блоков **зависит от роли**: менеджер видит **только зону A**; админ и управляющий — **A + B**.

### Зона A — «Отчёт продаж» (менеджер + админ + управляющий)

Менеджер **заполняет и сохраняет**. Управляющий — **только просмотр** (когда роль будет). Админ — ввод и правка (v1).

```
┌──────────────────────────────────────────────────────────┐
│  A1. ПЛАН МЕСЯЦА — «сосуд» (анимация)                   │
│      Факт Σ profit_day / plan_total                      │
│      План редактирует только админ (кнопка в зоне B)     │
├──────────────────────────────────────────────────────────┤
│  A2. Дата: [ … ]   ◀ ▶                                   │
├──────────────────────────────────────────────────────────┤
│  A3. Прибыль за день (₽):  НК  ДК  УК  → Итого (авто)    │
│  A4. ПНК (шт)                                            │
│  A5. Тренировок за день, клуб (шт) — вручную            │
│  A6. Матрица ПЗ/ТЗ/АЗ × НК/ДК/УК (шт)                    │
│  [ Сохранить отчёт ]  — только менеджер / админ          │
└──────────────────────────────────────────────────────────┘
```

### Зона B — «Финансы управляющего» (**менеджер не видит**)

Только **админ** (v1) и **управляющий** (позже). Блок **не рендерится** и **не отдаётся API** роли `sales_manager`.

```
┌──────────────────────────────────────────────────────────┐
│  B1. План на месяц (редактирование)                       │
│      plan_total, plan_pz, plan_tz, plan_az               │
├──────────────────────────────────────────────────────────┤
│  B2. Параметры управляющего за месяц                     │
│      expense_month (₽) — одна сумма расходов             │
│      (доп. поля — по мере согласования, v1: только расход)│
├──────────────────────────────────────────────────────────┤
│  B3. Итоги (считает сайт, только чтение)                 │
│      • Заработок месяца     = Σ profit_day               │
│      • Расход               = expense_month              │
│      • Чистая прибыль       = заработок − расход         │
│      • Σ profit_nk / dk / uk за месяц (опционально)      │
│      • Σ trainings_count за месяц (опционально)          │
│  [ Сохранить финансы / план ]                            │
└──────────────────────────────────────────────────────────┘
```

| Кто | Зона A | Зона B |
|-----|--------|--------|
| Менеджер по продажам | ✅ редактирует отчёт | ❌ **нет доступа** |
| Управляющий | 👁 просмотр | ✅ ввод расхода + **итоговые цифры** |
| Админ | ✅ всё | ✅ всё + выбор клуба |

**Важно:** это **одна страница**, не два URL. У менеджера нижняя часть (B) **отсутствует** — не «скрыта серым», а **не показывается**.

### «Сосуд» (анимация плана)

| | |
|---|---|
| Данные | `plan_total`; факт = **Σ `profit_day`** по сохранённым дням месяца |
| UI | Сосуд / банка, уровень = % плана; анимация при открытии и после сохранения дня |
| Кто меняет `plan_*` | **Админ** — блок B1; менеджер видит только сосуд в зоне A |

## Визуальный дизайн — **обязательное требование**

Экран продаж — **витрина для менеджера и руководства**, не «серая таблица в Excel». Должен выглядеть **красиво, современно, в духе FIT-CITY** (тёмная тема, зелёный акцент, мягкие карточки — как админ-панель и главная тренера).

### Общий язык

| Принцип | Реализация |
|---------|------------|
| Стиль | Тот же, что `admin-home`, `feature-tile`, `.card` — **не** чужой UI-kit |
| Фон | Тёмный градиент, лёгкое свечение акцента (`--accent-bright`, radial-gradient как у `admin-home__hero`) |
| Типографика | `section-title`, крупные **цифры итогов**, подписи `muted` |
| Отступы | `stagger` / `clamp()` — воздух между блоками, не плотная форма |
| Иконки | Lucide (как в приложении) — календарь, тренд, кошелёк |

### A1 — «Сосуд» с планом (главный визуальный акцент)

- **Центр экрана** в зоне A: стилизованный **сосуд / колба / банка** (SVG или CSS), не просто progress-bar.
- **Жидкость** — градиент зелёный → изумрудный, лёгкий **блик**; уровень = `факт / plan_total`.
- **Анимация:** плавное **заполнение** при открытии страницы (0.8–1.2 s, `ease-out`); после «Сохранить отчёт» — короткий **пульс / подъём уровня**, если изменился факт месяца.
- **Подпись:** «1 240 000 ₽ из 2 000 000 ₽» + **%** крупно; при ≥100% — мягкое «переполнение» (без кричащих цветов).
- **`prefers-reduced-motion`:** без анимации, только статичный уровень.

### A2–A6 — форма дня

- **Переключатель даты** — компактная «pill»-полоска (◀ дата ▶), как современный date stepper.
- **Прибыль НК / ДК / УК** — три **карточки-метрики** в ряд (на узком экране — колонка); у каждой подпись категории; **итого** — отдельная выделенная строка с авто-суммой.
- **ПНК и тренировки** — две небольшие карточки рядом (иконка + число).
- **Матрица 3×3** — аккуратная **таблица-сетка**: заголовки ПЗ/ТЗ/АЗ слева, НК/ДК/УК сверху; ячейки — округлые инпуты, hover/focus как у остальных форм.
- **Сохранить** — primary-кнопка; после сохранения — **toast** «Отчёт сохранён» (как в админке).

### Зона B — финансы (только admin / управляющий)

- **Визуально отделена**, но **в том же стиле**: тонкий разделитель или подзаголовок «Финансы клуба» (не другой сайт).
- **B3 Итоги** — **KPI-карточки** (заработок, расход, **чистая прибыль** крупнее остальных); чистая прибыль — главная цифра блока.
- План по направлениям — компактная **горизонтальная группа** полей или мини-таблица с подписями ПЗ / ТЗ / АЗ.
- **Прогноз на конец месяца** (`clubFinanceForecastCore`): при ≥2 будних и ≥2 выходных отчётах — **факт + среднее будня × оставшиеся будни + среднее выходного × оставшиеся выходные**; иначе fallback «среднее × дни месяца». Рядом — **темп**: сколько ₽ нужно в будний день, чтобы закрыть план (`computePlanPaceNeeded`). Код: `clubFinanceForecastProjection.js`. Verify: `scripts/verify-club-finance-forecast.mjs`.
- Без «сырых» `<table>` без стилей — только оформленные блоки.

## Модуль 2 — План продаж (месяц)

**В первой версии** ✅

| Поле | Описание |
|------|----------|
| `plan_total` | **Общая сумма** плана на месяц (₽) |
| `plan_pz` | План по **ПЗ** (₽) |
| `plan_tz` | План по **ТЗ** (₽) |
| `plan_az` | План по **АЗ** (₽) |

**Факт за месяц (авто):**

- **Общий:** `Σ profit_day` по дням месяца ↔ `plan_total`.
- **По направлениям ПЗ/ТЗ/АЗ:** в дневном отчёте **нет** выручки по залам → **авто-факт по направлениям не считаем** (см. «Не реализуем»). План по направлениям **показываем**; факт по направлениям — вручную/следующая версия, если добавят поля.

## Модуль 3 — Расход управляющего и прибыль

| Решение | |
|---------|---|
| Ввод | **Одна сумма (₽)** за **календарный месяц** на клуб |
| Детализация | У управляющего **вне системы**; в FIT-CITY — только итог |
| Кто вносит в v1 | **Админ** (переключил клуб → финансы) |
| Кто вносит позже | **Управляющий** своего клуба |

### Итог по месяцам (сайт считает)

```
Итого заработок месяца  = Σ profit_day  (все дни месяца)
Расход управляющего     = expense_month (одна введённая сумма)
Чистая прибыль месяца   = Σ profit_day − expense_month
```

Сводки: по месяцам, по клубу; при необходимости — таблица дней + матрица (агрегаты количеств по НК/ДК/УК и ПЗ/ТЗ/АЗ).

**Админ:** параметр `?club=` — продажи, план/факт, финансы **выбранного клуба**.
