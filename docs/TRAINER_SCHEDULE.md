# Ежедневник тренера (расписание персоналок)

**Актуально:** 2026-10-11  
**Статус:** ✅ MVP в коде (тренер, планшет, офлайн + sync)  
**Не:** Google Calendar как источник правды; групповые слоты; запись клиентом из ЛК (позже).

Связано: [PRODUCT_MODULES.md](./PRODUCT_MODULES.md), [SYNC.md](./SYNC.md), [DATA_MODEL.md](./DATA_MODEL.md), [DDX_PARITY_MAP.md](./DDX_PARITY_MAP.md) п.9–12.

## Ситуация

Тренер в зале планирует день: кому во сколько, личные пометки, несколько клиентов в один час. Сейчас — Excel/заметки/Google у каждого. Нужна **одна правда в Ядре**, чтобы позже клиентское приложение показывало «моя следующая тренировка» из тех же записей.

## MVP (фаза 1)

| Что | Как |
|-----|-----|
| Кто создаёт | Только **тренер** — на планшете (офлайн) или на телефоне (онлайн, фаза 2e) |
| UX | Как Google Calendar: **месяц** → тап по **дню** → сетка по часам. Режимы: **День / 3 дня / Неделя / Месяц**; в дневных режимах стрелки «назад/вперёд»; сетка **00:00–23:00**, при открытии скролл к ~07:00 |
| Запись в слот | **Заметка** (текст) **или** один/несколько **клиентов** тренера |
| Офлайн | IndexedDB + `sync_queue` → `push-record` |
| Pull | `trainer-pull`, окно −30…+120 дней от «сегодня» (МСК) |
| Связь с тренировкой | `linked_training_id` + «Начать / Продолжить» — см. фазу 2 |

## Как открыть (тренер)

| Где | Что |
|-----|-----|
| Главная `/trainer` | Плитка **Ежедневник** рядом с **Клиенты** и **Профиль** |
| Шапка | Пункт в верхнем меню и в бургер-меню (иконка календаря) |
| Прямой URL | `/trainer/calendar` |

**Планшет / сетка плиток:** на главной в режиме «доски» (`trainer-home--board`, ≥768px) три раздела всегда в **один ряд** (`repeat(3, …)`). Раньше сетка была на две колонки (под Клиенты/Профиль) — на широком планшете «Ежедневник» уезжал вниз. После деплоя на планшете нужно жёсткое обновление PWA ([PWA.md](./PWA.md)).

## Сущность `trainer_schedule_entries`

| Поле | Тип | Смысл |
|------|-----|--------|
| `id` | UUID | PK |
| `club_id` | UUID | Клуб |
| `trainer_id` | UUID | Тренер-владелец |
| `day_date` | DATE | Календарный день (МСК) |
| `start_minutes` | INT | Минуты от полуночи (0–1439) |
| `duration_minutes` | INT | Длительность, по умолчанию 60 |
| `title` | TEXT | Текст заметки (если без клиентов) |
| `client_ids` | JSONB | Массив UUID клиентов (0…10) |
| `linked_training_id` | UUID? | Связь с `trainings` (опционально) |
| `kind` | TEXT? | Категория: `training` / `group` / `trial` / `work` / `personal`; `NULL` — по умолчанию (миграция `20261011130000_trainer_schedule_kind.sql`) |
| `created_at` / `updated_at` | TIMESTAMPTZ | Ревизия / merge при pull |

**Правило отображения:** если `client_ids` не пуст — заголовок из имён клиентов; иначе `title` или «Заметка».

## Безопасность

- Push: **только тренер** (`trainerSchedulePushAuthCore.js`) — не admin/supervisor/manager; свой `trainer_id`, свой `club_id`, каждый `client_id` через `canAccessClient`, `linked_training_id` только на свою тренировку.
- Read API: `trainer-schedule` — admin / supervisor (`requireAdminOrSupervisor`), фильтр по клубу и списку тренеров клуба.
- Pull: `trainer-pull` — только `trainer_id` из JWT + `club_id` тренера.
- RLS: тренер — CRUD своих строк; админ — all (PostgREST); supervisor — только через API (service role).

## Фаза 2 (✅ в коде)

- Кнопка **«Начать / Продолжить тренировку»** на слоте с клиентом (день и модалка).
- Несколько клиентов — выбор, с кого начать.
- После первого сохранения черновика — `linked_training_id` на слоте (параметр URL `scheduleEntry`).
- Sync: `trainings` раньше `trainer_schedule_entries` (волны push); ошибка «тренировка пока не в облаке» **не** снимает слот с очереди.
- Чип статуса: «Черновик тренировки» / «Тренировка завершена».

## Фаза 2c — удобство как в Google Календаре (✅ в проде с 11.10.2026)

| Что | Как |
|-----|-----|
| Линия «сейчас» | В колонке сегодняшнего дня (МСК), обновляется раз в 30 с. Сетка открывается на «сейчас − 1 ч», если сегодня в окне; иначе на 07:00. Тренер и админ |
| «Сегодня» | Пункт в меню «⋮» шапки (с 12.10; раньше — кнопка): якорь на сегодня + скролл к текущему времени. Тренер и админ |
| Повтор | В форме тренера «Повторять каждую неделю»: дни недели (по умолчанию день записи) и 2/4/8/12/16 недель. Исходная запись — первая неделя; копии — **обычные отдельные записи** (новые `id`, без `linked_training_id`), каждая через `saveLocalWithSync`. Дни раньше сегодня и дубли (тот же день + время + клиенты/текст) пропускаются. **Серии в БД нет**: «изменить / удалить все следующие» — нет, только по одной |
| Перенос | Тренер, режимы День / 3 дня / Неделя (не Месяц). Удержание ~0,4 с → запись «поднята» (вибро), ведём по часам и колонкам дней, шаг 15 мин, автоскролл у краёв. Сдвиг пальца до подъёма — это скролл. Отпустили — `moveTrainerScheduleEntry` (только `day_date` + `start_minutes`, через очередь), плашка «Перенесено на … · Отменить» (6 с). Тап после жеста форму не открывает |
| Запрет переноса | `resolveScheduleDragPolicy`: завершённая связанная тренировка — запись не двигается (плашка); черновик (или тренировка ещё не в кэше) — только время в тот же день, иначе дата слота и черновика разъедутся |

## Фаза 2d — категории записей (✅ в проде с 11.10.2026, миграция применена)

| Категория | Цвет | С клиентами |
|-----------|------|-------------|
| Тренировка | изумрудный | обязательно (по умолчанию для новой записи) |
| Групповое | голубой | клиенты или текст |
| Пробное / консультация | жёлтый | клиенты или текст |
| Работа в клубе | бирюзовый | нет |
| Личное | серый | нет |

- Цвета одинаковы у тренера, админа и управляющего (не ролевой accent). Легенда под сеткой; в просмотре админа — строка «Категория».
- `kind = NULL` или противоречит клиентам (работа/личное с клиентами, тренировка без клиентов) → показ по умолчанию: клиенты → «Тренировка», заметка → «Личное». Старые записи так и выглядят.
- Состояние поверх цвета: черновик связанной тренировки — пунктир; завершена — галочка и бледнее; прошедшая запись — бледнее.
- Push: если в записи **нет поля** `kind` (старый бандл на другом планшете), сервер колонку не трогает — категорию не затрёт. Явный `null` — сброс.
- **Порядок выкатки:** сначала миграция (`scripts/r2-pg-migrate-vm.sh`), потом код. Иначе запись с `kind` не примет база и слот останется в очереди.
- Фильтр по категории у управляющего — позже (⏸).

**Жест на планшете:** после подъёма браузер на первом движении пальца начинает скролл и шлёт `pointercancel`. Поэтому в `useTrainerScheduleDrag` слушатель `touchmove` с `passive: false` ставится на `window` в момент касания (до `touchstart`), гасит скролл поднятой записи, а касание после подъёма ведётся `touch*`-событиями. Не переводить на `touch-action: none` у записей — тогда сетку нельзя листать пальцем по записи.

## Фаза 2e — Ежедневник на телефоне тренера (📋 в коде, ждёт выкатки)

| Что | Как |
|-----|-----|
| Где | Приложение тренера на телефоне — **главный экран** `/coach`, вкладка «Ежедневник» ([COACH_APP.md](./COACH_APP.md)) |
| Режимы | День / 3 дня / Неделя (пн–вс, 7 узких колонок, шапка «Пн / 05.10») / Месяц — выбор в меню «⋮» (три точки, без подложки) справа в шапке календаря; сверху в нём «Сегодня» — к текущему дню / месяцу и часу, дата по центру (`TrainerScheduleViewMenu.jsx`; так же и на планшете — вкладок под заголовком больше нет, стрелки ‹ › у даты остаются). «+» — маленькая плавающая кнопка в правом нижнем углу сетки, как в Google Календаре (`addFab`). В «Месяце» тап по «Октябрь 2026 ▾» — выбор года стрелками и месяца из 12 (`TrainerScheduleMonthPicker.jsx`, и на планшете). Стрелок нет — листание пальцем вбок, как в Google Календаре: экран едет за пальцем, отпустили дальше ¼ ширины или быстрым взмахом — соседний период, иначе пружинит назад; вверх-вниз — часы как раньше; во время переноса записи не листается; тап после взмаха форму не открывает. Логика жеста — `scheduleSwipeCore.js` + `useScheduleSwipe.js` (`verify-schedule-swipe.mjs`). Тот же календарь, что на планшете: создать, изменить, удалить, повтор, перенос пальцем с «Отменить» |
| Чего нет | Кнопки «Начать / Продолжить тренировку» и карточки клиента — тренировки ведутся на планшете (`canStartTraining={false}`) |
| Запись | Сразу на сервер, **без** IndexedDB и очереди: `POST /api/coach { op: 'schedule-save' \| 'schedule-delete' \| 'schedule-copies' }` → `coachScheduleWriteCore.js` → тот же `executePushRecord` + `authorizePush`, что у планшета. Нет сети — ошибка, ничего не копится |
| Чтение | `GET /api/coach?view=schedule-range&from&to` (≤62 дня): свои записи, имена своих клиентов, у тренировки только статус, активные клиенты для выбора — без телефонов и карт |
| Конфликт с планшетом | Телефон шлёт `base_updated_at` — метку записи, которую видел. На сервере другая (планшет или повтор успели раньше) → 409 «Запись изменилась на планшете — обновите Ежедневник», экран перечитывается, правка планшета не затирается. Удалённая запись → 404 «уже удалили» |
| Что меняет телефон | Только `day_date`, `start_minutes`, `duration_minutes`, `title`, `client_ids`, `kind`; владелец, клуб, `linked_training_id`, `created_at` — с сервера (`coachScheduleEditCore.js`) |
| Перенос | То же правило, что жест планшета, но проверяет **сервер**: завершённая тренировка — не двигается, черновик — только время того же дня |
| `updated_at` | Сервер ставит `max(сейчас, прежняя + 1 мс)` — pull планшета берёт облачную строку, только если она не старее локальной |

Правка телефона доходит до планшета при следующем Sync (pull). Если на планшете в очереди своя правка той же записи — при Sync выигрывает планшет (последняя запись). Окно между проверкой 409 и записью на сервере — доли секунды, не атомарно.

Общие куски планшета и телефона: модалка `TrainerScheduleEntryModal` (проп `actions`: планшет — `trainerScheduleLocalActions.js`, телефон — `src/lib/coach/coachScheduleActions.js`), поля формы `src/hooks/useScheduleEntryForm.js`, навигация `src/hooks/useScheduleCalendarNav.js`, перенос `useTrainerScheduleMove({ move })`. Экран телефона — `src/pages/coach/CoachCalendarPage.jsx` + `useCoachScheduleData.js`, стили `src/styles/coach-schedule.css`. Проверки — `verify-coach-schedule-edit.mjs`, экран — `node scripts/e2e/run-screens.mjs "Ежедневник с правкой"`.

## Фаза 2f — push-напоминания тренеру (📋 в коде, ждёт выкатки)

Тренер в зале не смотрит в Ежедневник каждые 10 минут — нужен толчок «через 15 минут Анна».

| Что | Как |
|-----|-----|
| Когда | За 15 минут до начала любой записи (все категории, заметки тоже). Cron на ВМ каждые 5 минут → push приходит за 10–15 минут; заголовок «Через 12 мин · 10:00», текст «Тренировка: Анна, Олег» / «Работа: Планёрка» |
| Кому | Владельцу записи на все его устройства с включёнными «Уведомлениями» (планшет и телефон) |
| Не шлём | Запись уже стала тренировкой (`linked_training_id`), запись началась, повтор того же слота (журнал `trainer_schedule_reminder_log`). Перенесли запись на другое время — новое напоминание |
| Выключатель | «Напоминания из Ежедневника» под «Уведомлениями»: планшет — «Настройки» бургера (только тренер), телефон — «Меню». Свой на каждом устройстве (`user_push_subscriptions.schedule_reminders`, по умолчанию **включено**). Без включённых уведомлений неактивен |
| Тап по push | Планшет — `/trainer/calendar`, телефон — `/coach` (Ежедневник) |

Код: правила — `api/_lib/trainerSchedule/scheduleReminderCore.js`, отправка — `scheduleReminderJob.js`, настройка устройства — `api/_lib/pushPrefsHandler.js` (`op: 'prefs'` / coach `push-prefs`), экран — `src/components/header/ScheduleReminderSwitch.jsx` + `src/hooks/useScheduleReminderSetting.js`. Проверка — `scripts/verify-schedule-reminders.mjs`.

**Выкатка (один раз):** миграция `20261015120000_trainer_schedule_reminders.sql` (`scripts/r2-pg-migrate-vm.sh`) → деплой → на ВМ `sudo bash scripts/schedule-reminders-install-vm.sh` (cron + пробный `--dry-run`). Журнал: `journalctl -t fd-schedule-reminders`. До миграции cron пишет `skipped: migration_pending`, выключатель показывает «Пока недоступны».
