## 1. Суть и коммерческая цель

**Одна фраза:** FIT-CITY — тёмная премиальная ОС фитнес-клуба: спокойный фон, цифры и следующий шаг в центре, редкий яркий CTA.

| Контекст | Что должно чувствоваться |
|----------|---------------------------|
| Презентация / продажа клубу | «Это коммерческий продукт», три роли — три узнаваемых кадра |
| Тренер на планшете | Крупно, быстро, без лишних тапов; красота не мешает |
| Админ / менеджер на мониторе | Плотные цифры, тот же бренд, разный нюанс роли |

Красота **не имеет права** ухудшить touch (≥44px), увеличить число тапов или спрятать ошибку sync/офлайн.

---

## 2. Опора: Whoop (дисциплина, не копия)

**Опорная компания:** [Whoop](https://www.whoop.com) (приложение recovery / strain).

| Берём | Не берём |
|-------|----------|
| Near-black canvas, мало декора «ради декора» | Логотип, wordmark, точные ассеты Whoop |
| Данные / KPI как главный герой | Их indigo/violet как primary CTA |
| Цвет = смысл (статус, контур), не радуга рамок | Их фирменные шрифты (Proxima / DIN) |
| Редкий яркий CTA, остальное спокойное | Пиксель-в-пиксель чужие экраны |
| Презентабельно и в работе, и на слайде | Gamification / чужие паттерны recovery-колец 1:1 |

**Формула для команды и агента:** *«как Whoop по дисциплине, но ОС фитнес-клуба FIT-CITY»*.

Почему не Spotify / Peloton / Linear: Spotify — витрина; Peloton — шоу-контент; Linear — отличный craft, но не спортивный бренд и не emerald-язык зала.

## 3. Имя, тема, база

| Тема | Канон |
|------|--------|
| Имя в UI | **FIT-CITY** (как splash). «Фитнес-дневник» — не главный brand-mark шапки |
| Тема | Только **тёмная** glass. Светлую не проектируем |
| База акцента | Emerald: neon `#2effb8`, solid `#14d89a`, dim `#0a7d5c` |
| Legacy | `#00a651` — **вывести** из brand-chrome (заменить на token) |
| Шрифт UI v1 | **Inter** (читаемость на планшете) |
| Display-шрифт | Только splash / презентационный deck — отдельным решением, не в v1 shell |
| Иконки | Lucide в действиях; FA dumbbell допустим как mark, цвет только из токенов |
| ИСКРА | Надстройка поверх shell роли; орб/motion — в ISKRA_NORTH_STAR, не вторая палитра клуба |

### 3.1. Базовые токены (семантика)

Источник в коде после фазы B — `tokens.css` (`--premium-*` → алиасы `--bg`, `--accent`, …).

| Токен (смысл) | Значение (канон) | Назначение |
|---------------|------------------|------------|
| Фон | `#030806` / subtle `#061210` | Canvas |
| Текст | `#f6f4ef` / muted `#a8b2ac` | Читаемость |
| Карточка | glass `rgba(8,32,24,0.52)` + blur | Поверхности |
| Accent (база = тренер) | `#14d89a` / bright `#2effb8` | CTA, mark, focus |
| Danger / warning | `#f87171` / `#fbbf24` | Общие для всех ролей |
| Радиусы | 22 / 16 / 12 | Без «своих» на модуль |

**Запрет:** новые сырые hex в компонентах вне токенов (кроме одноразовых data-viz с комментарием «не brand»).

## 4. Ролевые цвета (обязательно)

**Правило:** оттенок = **кто залогинен**, не какой модуль открыт.  
Админ на продажах / ПНК остаётся в admin-shell (champagne), даже если контент модуля «про продажи».

Механика: CSS-переменные на `.app-shell--trainer` (или default), `.app-shell--sales`, `.app-shell--admin` (см. `App.jsx`).

| Роль | Нюанс | Bright | Solid | Dim | Radial (фон) | Аналогия Whoop |
|------|--------|--------|-------|-----|--------------|----------------|
| **Тренер** | Emerald | `#2effb8` | `#14d89a` | `#0a7d5c` | `rgba(46,255,184,0.14)` | Teal CTA |
| **Менеджер** | Cyan–teal | `#22d3ee` | `#06b6d4` | `#0e7490` | `rgba(34,211,238,0.12)` | Strain blue |
| **Админ** | Champagne / soft gold | `#f0d48a` | `#d4b45c` | `#8a7340` | `rgba(240,212,138,0.12)` | Третий статусный контур (не violet) |

### Что красим ролью

- `--accent`, `--accent-bright`, `--accent-dim`, `--accent-glow` / soft  
- `--premium-bg-radial` (ambient фона shell)  
- цвет brand-mark и focus-ring в шапке  
- underline / индикатор активного пункта nav (тонко)

### Что не красим ролью

- `--text`, `--danger`, `--warning`, радиусы, шрифт  
- длинные таблицы «ради красивого неона»  
- локальные status-цвета модулей (ок/внимание в ПНК) — можно, но **не** подменять shell-accent

### Do / Don't

| Do | Don't |
|----|--------|
| Три home на презентации различимы за ~2 сек по оттенку шапки | Админ = копия тренера |
| Админ открыл продажи — shell champagne | Вешать `app-shell--sales` на админа |
| Общие bg / type / radius | Три несвязанных UI-языка на модуль |

## 5. Плюсы усилить / минусы закрыть

### Плюсы → как усилить

| Плюс | Усиление |
|------|----------|
| Уже есть тёмный emerald + glass | Назвать базой **Whoop-класса**, не «временно покрасили» |
| Продажи / ПНК ближе к премиуму | Эталон зрелости; остальные экраны тянуть к ним |
| Ролевые оттенки | Три кадра презентации = тренер / менеджер / админ |
| Офлайн-зал — ядро | В том же абзаце канона: один CTA, touch ≥44px |
| Один документ | Закон для человека и агента |

### Минусы → противоядие в каноне

| Риск | Правило |
|------|---------|
| Glow → казино / геймер | Glow только на CTA, focus, brand-mark; таблицы без свечения |
| Роли → три продукта | Общие bg/text/radius/type; меняются accent/radial/mark |
| Админ = тренер | Champagne-shell обязателен |
| Админ «синеет» на продажах | Роль ≠ модуль |
| Красота вредит планшету | Critic-чеклист (§9 и приложение A) |
| Слишком близко к Whoop юридически | «Inspired by Whoop discipline», без ассетов |
| Dual green / старое имя | FIT-CITY + token emerald; `#00a651` убрать из chrome |

## 6. Типографика и плотность

| Уровень | Назначение | Ориентир |
|---------|------------|----------|
| Hero / brand | Splash, имя продукта | Крупно, вес 700–800 |
| H1 | Заголовок экрана | ~1.35–1.5rem, 700 |
| H2 | Секция | ~1.15–1.25rem, 600–700 |
| Body | Основной текст | ~0.95–1rem, 400 |
| Meta | Подписи, даты | ~0.8–0.85rem, muted |
| KPI | Главная цифра | Крупно, tabular nums где уместно |

**Плотность:**

- **Зал (тренер):** крупнее зоны, меньше текста, один главный CTA на шаг.  
- **Админ / менеджер:** плотнее цифры на широком мониторе; master–detail ≥1100px где уже принято (ПНК).

## 9. Critic-чеклист (перед «красиво готово»)

1. Красиво на слайде — и удобно тренеру на планшете?  
2. Хуже ли по тапам / зоне ≥44px / читаемости с 60 см?  
3. Без glow/градиентов всё ещё премиум?  
4. Три роли отличимы по шапке за ~2 сек?  
5. Админ на продажах всё ещё «админ»?  
6. Не казино / неон-геймер / ChatGPT-purple?  
7. Один главный CTA? Вторичное не орёт тем же цветом?  
8. Цвет = смысл (роль/статус), не просто рамки?  
9. Empty / loading / error того же класса?  
10. Можно сказать: «как Whoop, но ОС клуба FIT-CITY»?

## Приложение A — Driving prompt

Вставлять в чат при любой правке канона или UI shell/экранов.

```text
Роль
Ты — жёсткий дизайн-директор коммерческого B2B-продукта для фитнес-клубов (FIT-CITY).
Не декоратор. Не «ещё один dark mode». Цель: продукт, который продаётся на презентации
и не бесит тренера на планшете между клиентами.

Продукт (истина)
- PWA: тренер офлайн на планшете; админ/менеджер на мониторе; ИСКРА — надстройка.
- Уже есть: тёмный emerald/glass, tokens.css, app-shell--sales / --admin.
- Канон: docs/BRAND_SYSTEM.md; код оболочки — после утверждения канона.
- Опорный визуальный язык: Whoop (тёмный canvas, данные в центре, цвет = смысл,
  редкий яркий CTA). Копируем дисциплину, НЕ логотип/шрифты/пиксели Whoop.
- Роли: тренер = emerald (#2effb8 / #14d89a); менеджер = cyan-teal (#22d3ee / #06b6d4);
  админ = champagne/soft gold (#f0d48a / #d4b45c).
  Оттенок = роль сессии, не открытый модуль.

Цель волны
1) Довести фирменный стиль до конца (документ + токены).
2) Коммерческая красота для презентации.
3) UX не хуже: тапы, touch, офлайн-ошибки, скорость в зале.

Обязательный разбор (каждый ответ)
A. ПЛЮСЫ текущего направления — перечисли и усили: как сделать плюс ещё заметнее
   на презентации и в ежедневной работе.
B. МИНУСЫ / риски — перечисли честно. Для каждого: как смягчить или запретить
   правилом в каноне (не «потом посмотрим»).
C. КРИТИКА — ответь на вопросы ниже; если ответ слабый — упрости решение.
D. ЭТАЛОН Whoop — что именно заимствуем в этом куске; чего сознательно НЕ берём.

Вопросы-критики (обязательны)
1. Это красиво на слайде инвестору — и удобно тренеру мокрыми руками на планшете?
2. Что станет хуже по числу тапов / размеру зоны нажатия / читаемости с 60 см?
3. Если убрать весь glow и градиенты — продукт всё ещё выглядит премиально?
   (Если нет — красота держится на дешёвом эффекте.)
4. Отличаются ли три роли за 2 секунды на скрине шапки — без чтения слова «Админ»?
5. Админ на экране продаж всё ещё «админ» или уже «менеджер»?
6. Не выглядит ли экран как геймерский неон / казино / ChatGPT-purple?
7. Главный CTA один? Вторичное не орёт тем же цветом?
8. Цвет несёт смысл (роль / статус / деньги) или просто красит рамки?
9. Пустые/loading/error состояния дотягивают до того же класса, что hero?
10. Можно ли объяснить стиль фразой: «как Whoop, но ОС фитнес-клуба FIT-CITY»?

Запреты
- Ломать sync / офлайн / завершение тренировки ради визуала.
- Три несвязанных UI-языка на модуль.
- Сырые hex вне токенов в новом коде.
- Красота ценой мелких кнопок (<44px) на планшете.
- Копировать trademark Whoop (лого, wordmark, точные ассеты).

Формат выхода для канона / UI-правки
- Таблицы токенов + ролей (если менялись)
- Do / Don't
- Эталонные экраны (3 home по ролям), если затронуты
- Список минусов с правилом-противоядием
- Короткий DoD: «готово к коммерческой презентации shell» vs «ещё сырой модуль»

Вердикт в конце каждого прогона
Делаем / Упростить / Отложить / Не делаем — с одной фразой почему.
```
