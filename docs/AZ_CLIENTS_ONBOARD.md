# Клиенты АЗ — как вести в Оси (по шагам)

**Статус:** ✅ desk АЗ в проде (вкладка **АЗ**, направления, списание занятий, сид из Excel закрытий).  
**Не путать с ПЗ:** АЗ = `desk_hall = az`, **без** живого тренера. ПЗ — с `trainer_id` ([PZ_CLIENTS_ONBOARD.md](./PZ_CLIENTS_ONBOARD.md)).  
**Не путать с ТЗ:** ТЗ — только срок абона; АЗ — срок **и** остаток занятий + направление.

**Мост → цель:** закрытия и `31.xlsx` — переход; деньги — [PAYMENTS_DOMAIN.md](./PAYMENTS_DOMAIN.md) (MVP оплат: **ПЗ и АЗ**).

---

## Кому это

Админ / менеджер: аэробный зал (Бокс, Степ…) без планшета тренера — карточки desk, абоны, списания визитов, цифры в матрице отчёта.

---

## Шаг 0. Подготовка

1. **Структура → Типы абон.** → раздел **АЗ** — типы с направлениями (Бокс, Техника дня…).
2. Sync у устройств, где смотрят типы.
3. Прайс АЗ (по желанию) — вкладка Прайс → АЗ ([PRICE_LIST.md](./PRICE_LIST.md)).

---

## Как появляются клиенты АЗ

### А. Раз в период — Excel закрытий (мост)

1. **Админ → Списки из Excel** — один файл ТЗ+АЗ из 1С.
2. Зал из «Тип карты» (`АЗ` → `az`).
3. После «Применить»: **Клиенты → вкладка АЗ** — `trainer_id = null`, `desk_hall = az`, абон с датами и `paid_amount` (**цена**, не платёж).

### Б. Из вечерних оплат (мост)

1. **Продажи → Отчёт** — `31.xlsx` → строки с залом АЗ.
2. Блок **«Карточки из оплат»** — desk АЗ (направление и срок: дни или месяцы — из тарифа или вручную).
3. Цель позже: та же строка станет `payment` с `hall = az` ([PAYMENTS_DOMAIN.md](./PAYMENTS_DOMAIN.md) § ПЗ и АЗ).

### В. Вручную

**Клиенты** → вкладка **АЗ** (или «+» с любой живой вкладки → сегмент АЗ) → ФИО, карта, направление, сроки, занятия, цена.  
Либо карточка desk: контакты, абон (сроки + кол-во занятий, **без** пакета «N месяцев»), направление, цена.  
Массово по-прежнему — Excel закрытий.

---

## Списание занятия

1. Вкладка **АЗ** или карточка → **«Списать занятие»** (если нельзя — причина на русском).
2. В визит пишется **направление** на момент списания; журнал дат на абоне.
3. Дневной отчёт: пустые ячейки матрицы АЗ могут подтянуться из списаний; «Довести матрицу» — без затирания ручных чисел вниз.

Абон **жив**, пока есть срок **и** остаток занятий (как у ПЗ; у ТЗ — только срок).

---

## Оплата и отчёт (проекция цели)

| Сейчас | Цель для АЗ |
|--------|-------------|
| Сумма в Excel / форме дня | `payment` с `hall = az`, сегмент НК/ДК/УК |
| `paid_amount` на абоне | Цена пакета; платёж ссылается на `membership_id` |
| Списание ≠ оплата | Визит не создаёт платёж; платёж — факт денег на ресепшене / из импорта |

---

## Чего не делать

| Не так | Почему |
|--------|--------|
| Вешать АЗ на тренера «для удобства» | Ломает desk / KPI |
| Грузить АЗ как lite-ПЗ | ПЗ требует тренера |
| Ждать «Книгу часов» для АЗ | АЗ уже в Оси через списания |
| Считать `paid_amount` кассой | См. PAYMENTS_DOMAIN |
