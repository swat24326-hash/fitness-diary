# Роль «Управляющий» (club supervisor) — ТЗ, отложено

**Статус:** согласовано с заказчиком, **реализация позже**.  
**Не путать с:** «Менеджер по продажам» — **отдельная роль**, позже.

---

## Суть

**Управляющий** — старший тренер **одного клуба**: сам ведёт тренировки и смотрит **статистику всего клуба**.  
На клуб — **один** управляющий. Учётку создаёт **только админ** (`users.role`, `users.club_id` обязателен).

В коде (план): `users.role = 'supervisor'`, в UI — **«Управляющий»**.

---

## Интерфейс

| Решение | |
|---------|---|
| После входа | **Главная тренера** (как сейчас `/trainer`) — клиенты, черновики, своя работа |
| Раздел **«Клуб»** | Отдельная зона (вкладка / пункт меню) со **всеми вкладками, которые касаются клуба** — без выбора клуба (всегда свой `club_id`) |
| В «Клубе» (план) | Клиенты клуба, статистика клуба, челленджи, диагностика — **не** упражнения, **не** структура/тренеры/клубы |
| Статистика личная | **Своя** как у тренера (на главной / в профиле) **+** статистика **всего клуба** в разделе «Клуб» |
| Планшет в зале | Работает **как тренер** (черновики, sync) |
| Нет вкладок | Упражнения (справочник), создание клубов, создание/удаление тренеров, редактирование данных клуба |

**Схема навигации (черновик):**

```
/trainer          — главная тренера (как сейчас)
/trainer/club/*   — раздел «Клуб»: clients, statistics, challenges, diagnostics
                    (club_id = users.club_id, без ?club= в URL)
```

## Клиенты

| Действие | Управляющий |
|----------|-------------|
| Видит **всех** клиентов клуба | ✅ |
| Создаёт клиента | ✅ по умолчанию **на себя** (`trainer_id = я`), может **переназначить** другому тренеру клуба |
| Редактирует карточку **любого** клиента клуба | ✅ |
| **Абонементы** у любого клиента клуба | ✅ **создаёт и правит** (как админ в рамках клуба) |
| Тип абонемента при оформлении | ✅ **выбирает из списка**, как тренер (справочник типов **не редактирует**) |
| Архив / «Вернуть» | ✅ любого в клубе |
| Удалить клиента безвозвратно | ✅ |
| Переназначить `trainer_id` другому тренеру клуба | ✅ |

## Тренировки

| Действие | Управляющий |
|----------|-------------|
| **Проводить** новую тренировку | ✅ только **свои** (`trainer_id = я`) |
| **Править / удалить** тренировку | ✅ **любую** в клубе (свою и чужую) |
| **Видеть чужие** тренировки | Только в **статистике / журнале клуба** или в **карточке клиента** (не в своём списке «Мои тренировки») |
| Push/sync | Свои insert/update как тренер; правка/удаление чужих — по правилам API (не обходить очередь) |

## Технические следствия (когда будем делать)

1. **Миграция:** `CHECK (role IN ('admin', 'trainer', 'supervisor'))`, RLS по `club_id`, функции `fit_auth_is_supervisor()` / scope.
2. **API:** `isSupervisor` в `api/_lib/adminSupabase.js`; не давать права `isAdmin` глобально.
3. **`mutationAuth`:** insert `trainings` только `trainer_id = user.id`; update/delete `trainings` в своём `club_id`; clients/memberships — club scope + переназначение `trainer_id`.
4. **`admin-data?action=`:** `club-stats`, `journal`, clients list — для supervisor + фильтр `club_id = profile.club_id`.
5. **`trainer-pull`:** supervisor **может** (офлайн своих клиентов); pull клиентов клуба для админ-раздела — отдельный путь или расширение list-clients.
6. **UI:** главная `/trainer` + раздел **`/trainer/club/*`** (клиенты, статистика, челленджи, диагностика); переиспользовать админ-компоненты с `clubId = user.club_id`.
7. **Verify:** push-права supervisor, club scope, не ломать offline-first.

**Лимит Vercel 12 functions:** новые endpoint не добавлять — только `admin-data?action=`.
