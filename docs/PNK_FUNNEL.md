# Воронка ПНК (потенциальный новый клиент)

**Статус:** в проде (2026-07) — линейный мастер 1|2 бесплатных, день визита пакетом.  
**Принцип:** та же карточка клиента; жизненный цикл `pnk` + абонемент БЗ. Оформление = платный ДК.  
**UX:** на каждом шаге только то действие, которое тренер должен сделать сейчас.

---

## Сценарий проверки (сквозной)

**Клиент:** «Сценарий ПНК Иванов», телефон `+79001234567`.

### 0. Подготовка
- В типах абонементов есть **БЗ** с флагом `is_pnk_trial` или кодом БЗ.
- Миграции ПНК применены (`npm run db:migrate:pnk -- --linked`).

### 1. Менеджер создаёт ПНК
1. `/sales` → плитка **ПНК** (или `/sales/pnk`).
2. Выбрать **1 или 2** бесплатные → тренер → передать.
3. Баннер Max / другой мессенджер — написать тренеру.

### 2. Тренер ведёт мастер (понятно по наитию)

| Шаг | Что на экране |
|-----|----------------|
| Связь с клиентом | Max → **Связался — далее** в шапке |
| Дата бесплатной | Дата/время → **Сохранить дату** |
| **Ждём в зале** | Изменить дату / Max → **Клиент пришёл** |
| Здоровье и обмеры | Карта + обмеры на одной вкладке → **К питанию** (пропуск нельзя; обмеры желательны) |
| Питание | Рацион → **К тренировке** или **Пропустить** |
| Тренировка | **Начать тренировку** → **Далее** (пропуск нельзя) |
| ДЗ | Вкладка ДЗ → **Далее** / **Пропустить** |
| (если 2) Тренировка 2 + ДЗ 2 | то же |
| Касание после | Max → **Далее** / **Пропустить** |
| Оформление | Абонемент ДК → **Оформлен (ДК)** или отказ |

Первый шаг шкалы — **Создан ПНК** (создать может менеджер или тренер); рабочий старт — «Связь с клиентом».

**Шапка воронки** (липкая): прогресс `N/M` + полоска + **одна главная кнопка** (например «Клиент пришёл» / «К питанию») и вторичные Назад / Пропустить / Отказ. На шаге тренировки до БЗ главная кнопка — **«Начать тренировку»** в теле шага. Тот же прогресс — на плитке доски менеджера и glance.

**Итог визита (качество):** блок «сделано / слабо / нет / ждём» — у **админа** и **менеджера**. Фазы в **три колонки** (До визита | В зале | После; на узком экране — столбиком). В зале один пункт **«Здоровье и обмеры»** (карта + замеры). Пока нет **начала тренировки** (`visit_started`), пункты пакета зала и «После» не штрафуют оценку (статус «ждём»). «Начало тренировки» = старт пакета первой бесплатной (дата/время слота).

**Доска:** при открытии, если есть срочные — фильтр «Внимание» и справа сразу первый горящий; смена фильтра снова выбирает первого в списке.

**Статистика:** KPI `оформления/ПНК` и маленький `%` — доска ПНК, статистика клуба и тренера. Карточка KPI кликабельна → разбор (отказы, открытые, питание/ДЗ, по тренерам).

Вкладки карточки — **только текущий подшаг**.

**Отказ без карточки:** при «Отказ» (и при удалении ПНК с доски) — событие в `pnk_funnel_events` (клуб/тренер/даты/флаги пакета, без имени и телефона) + полное удаление карточки и абонементов. Пока delete в очереди sync — pull **не** восстанавливает карточку из облака. Статистика = открытые/оформленные клиенты + журнал. Старые `pnk_lost` в базе ещё учитываются, пока их не удалят.
