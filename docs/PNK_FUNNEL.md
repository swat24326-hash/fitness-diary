# Воронка ПНК (потенциальный новый клиент)

**Статус:** в проде (2026-07) — линейный мастер 1|2 бесплатных, день визита пакетом.  
**Принцип:** та же карточка клиента; жизненный цикл `pnk` + абонемент БЗ. Оформление = платный ДК.  
**UX:** на каждом шаге только то действие, которое тренер должен сделать сейчас.

---

## Сценарий проверки (сквозной)

**Клиент:** «Сценарий ПНК Иванов», телефон `+79001234567`.

### 0. Подготовка
- В типах абонементов есть **БЗ** с флагом `is_pnk_trial` или кодом БЗ.
- Миграции ПНК применены (`npm run db:migrate:pnk -- --linked`).

### 1. Менеджер создаёт ПНК
1. `/sales` → плитка **ПНК** (или `/sales/pnk`).
2. Выбрать **1 или 2** бесплатные → тренер → передать.
3. Баннер Max / другой мессенджер — написать тренеру.

### 2. Тренер ведёт мастер (понятно по наитию)

| Шаг | Что на экране |
|-----|----------------|
| Связь с клиентом | Max → **Связался — далее** в шапке |
| Дата бесплатной | Дата/время → **Сохранить дату** |
| **Ждём в зале** | Изменить дату / Max → **Клиент пришёл** |
| Здоровье и обмеры | Карта + обмеры на одной вкладке → **К питанию** (пропуск нельзя; обмеры желательны) |
| Питание | Рацион → **К тренировке** или **Пропустить** |
| Тренировка | **Начать тренировку** → **Далее** (пропуск нельзя) |
| ДЗ | Вкладка ДЗ → **Далее** / **Пропустить** |
| (если 2) Тренировка 2 + ДЗ 2 | то же |
| Касание после | Max → **Далее** / **Пропустить** |
| Оформление | Абонемент ДК → **Оформлен (ДК)** или отказ |

Первый шаг шкалы — **Создан ПНК** (создать может менеджер или тренер); рабочий старт — «Связь с клиентом».

**Шапка воронки** (липкая): прогресс `N/M` + полоска + **одна главная кнопка** (например «Клиент пришёл» / «К питанию») и вторичные Назад / Пропустить / Отказ. На шаге тренировки до БЗ главная кнопка — **«Начать тренировку»** в теле шага. Тот же прогресс — на плитке доски менеджера и glance. Плитки доски в одном ряду **одной высоты** (имя занимает место под 2 строки, шкала внизу); без обрезки шкалы шагов.

**Итог визита (качество):** блок «сделано / частично / нет / ждём» — у **админа** и **менеджера**. Фазы в **три колонки** (До визита | В зале | После; на узком экране — столбиком). В зале один пункт **«Здоровье и обмеры»** (карта + замеры). Пока нет **начала тренировки** (`visit_started`) и нет завершённой БЗ в `bz_completed_by_client`, само начало и пункты пакета зала/«После» не штрафуют (статус «ждём»). Штраф «нет» на этапе до зала — только реально пропущенное (связь, дата бесплатной). «Начало тренировки» = старт пакета первой бесплатной (дата/время слота). **Шов после зала:** список «Внимание» / hot на главной и открытие пакета визита в мастере учитывают `bz_completed_by_client` так же, как доска — завершённая БЗ без stamp `trial` не оставляет «Неявка».

**Доска:** по умолчанию «Все» в работе (в т.ч. тихое «Оформление» 10/10). Фильтр «Внимание» — вручную; справа при `?focus=` или первый горящий / первый в списке.

**Статистика:** KPI `оформления/ПНК` и маленький `%` — доска ПНК, статистика клуба и тренера. Карточка KPI кликабельна → разбор (отказы, открытые, питание/ДЗ, по тренерам). Бандл `pnk-bundle` отдаёт `bz_completed_by_client` **до** сборки attention; то же число — в glance главной после «Обновить» на доске.

Вкладки карточки — **только текущий подшаг**.

**Отказ без карточки:** при «Отказ» (и при удалении ПНК с доски) — событие в `pnk_funnel_events` (клуб/тренер/даты/флаги пакета, без имени и телефона). Если у клиента только ПНК/БЗ — полное удаление карточки. Если уже есть ТЗ/АЗ или иная не-ПНК история — **карточка сохраняется**, снимаются только ПНК-поля и БЗ ([CLIENT_MULTI_HALL.md](./CLIENT_MULTI_HALL.md)). Пока delete в очереди sync — pull **не** восстанавливает карточку из облака. Статистика = открытые/оформленные клиенты + журнал. Старые `pnk_lost` в базе ещё учитываются, пока их не удалят.

**Создание ПНК:** при совпадении № карты или телефона с существующим клиентом клуба — **attach** (тот же `clients`), не вторая карточка.

---

### 3. Цифры и роли
Как раньше: доска менеджера/админа, glance на главной. **Главная и доска — один список открытых:** «Обновить» на доске пишет кэш + событие `fd-pnk-home-glance-changed`; сеть на главной не чаще **25 с** (debounce под активную админку / ×10 клубов). Отметка бесплатной (`trial` / `trial2`) автоматически ставит `visit_started`, если его ещё не было. **Итог визита** на доске получает `bz_completed_by_client` (завершённые тренировки 0…2) — пункт «Тренировка» не остаётся «частично» без факта зала. Автопроверки: `verify-pnk-wizard`, `verify-pnk-stages`, `verify-pnk-bz-completed`, `verify-pnk-visit-quality`, `verify-pnk-post-training-edge`, … в `qa:local`.
