# Воронка ПНК (потенциальный новый клиент)

**Статус:** MVP в коде (2026-07).  
**Принцип:** та же карточка клиента; отличается жизненный цикл и абонемент БЗ (неплатный). Оформление = платный абонемент → ДК.

## Этапы (для тренера — по одному на экране)

| № | UI | Смысл | Действие |
|---|-----|--------|----------|
| 1 | Создан | ПНК попал в воронку | Перейти к контакту |
| 2 | Контакт и дата | Первый контакт + дата бесплатной | **В Max** / **Другой мессенджер**, сохранить дату |
| 3 | Бесплатная | Визит в клуб | Вкладки: здоровье, питание, ДЗ, абонементы → «проведена» |
| 4 | Уточнение | Повторный контакт | Снова Max / другой мессенджер → «уточнение сделано» |
| 5 | Оформление | Итог | Оформлен (ДК) или отказ |

На шаге 3 вкладки **Тренировки** и **Статистика** скрыты — появятся после оформления в активного клиента (журнал нужен уже как у ДК).

## Коды в БД (`pnk_stage`)

`new` · `assigned` · `contact` · `agreed` · `trial_done` · `followup` · `won` · `lost`

## Чеклист (`pnk_deliverables`)

`contact` · `trial` · `nutrition` · `homework` · `followup`

## Роли

| Роль | Действие |
|------|----------|
| Менеджер / админ | Создаёт ПНК, назначает тренера, пишет тренеру (Max / другой мессенджер), видит % |
| Тренер | Шаги выше; сообщения **клиенту** через Max / другой мессенджер |

## Данные

Колонки на `clients` + `membership_types.is_pnk_trial`.  
Логика: `src/lib/pnk/*`. API: `admin-data?action=pnk`.  
В справочнике типов отметьте **БЗ** флагом `is_pnk_trial`.

## Миграция

```bash
npm run db:migrate:pnk -- --linked
```

## Сценарий (менеджер + тренер)

**Клиент:** «Сценарий ПНК Иванов», телефон `+79001234567`.

### Менеджер
1. `/sales` → **ПНК** → создать / сценарий → назначить тренера.
2. Сообщить тренеру: **В Max** / **Другой мессенджер**.

### Тренер
1. Клиенты → фильтр **ПНК** → карточка.
2. Пройти шаги 1→5; на контактах писать клиенту через мессенджер.
3. Неявка на бесплатную — перенос даты или закрытие.

### Статистика
ПНК за период · оформления · % · по тренеру; качество: % с питанием / ДЗ.
