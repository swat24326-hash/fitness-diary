# Воронка ПНК (потенциальный новый клиент)

**Статус:** в проде / MVP (2026-07).  
**Принцип:** та же карточка клиента; жизненный цикл `pnk` + абонемент БЗ (неплатный). Оформление = платный ДК.

---

## Сценарий проверки (сквозной)

**Клиент:** «Сценарий ПНК Иванов», телефон `+79001234567`.

### 0. Подготовка
- В типах абонементов есть **БЗ** с флагом `is_pnk_trial`.
- Миграции ПНК применены (`npm run db:migrate:pnk -- --linked`).

### 1. Менеджер создаёт ПНК
1. `/sales` → плитка **ПНК** (или `/sales/pnk`).
2. Чип **Создать ПНК по сценарию** → выбрать тренера → **Передать тренеру**.
3. Баннер: **В Max** / **Другой мессенджер** — написать тренеру о новом ПНК.

### 2. Админ контролирует (опционально)
1. Клуб в шапке → `/admin/pnk` (плитка **ПНК** на главной админа).
2. Доска: прокрутка, фильтр, поиск, тренер.
3. Раскрыть карточку → написать тренеру, комментарий, открыть карточку клиента.

### 3. Тренер видит продвижение
1. **Главная** `/trainer`:
   - виджет **«ПНК в работе»** (как задание от руководства) — шаг, полоска, тап → карточка;
   - блок **«Сегодня внимание»** — плитка **ПНК** с числом в воронке → список с фильтром.
2. **Клиенты** → фильтр **ПНК**.

### 4. Тренер ведёт воронку (один шаг на экране)
| Шаг | Что делает |
|-----|------------|
| 1 Создан | «Дальше: контакт и дата» |
| 2 Контакт и дата | Клиенту **В Max** / **Другой мессенджер** → дата бесплатной → сохранить |
| 3 Бесплатная | Здоровье, питание, ДЗ, абонементы (БЗ). Тренировки/статистика скрыты до оформления |
| 4 Уточнение | Снова Max / другой мессенджер → «уточнение сделано» |
| 5 Оформление | **Оформлен (ДК)** или **Отказ** |

Неявка: перенос даты или закрытие. На любом шаге — «Отказ на этом шаге».

### 5. Цифры (score)
На доске менеджера/админа за месяц:
- **ПНК** — вошли в воронку  
- **Оформления** — won  
- **Конверсия %** — won / entered  
- **В работе** — открытые  
- Качество: % с питанием / с ДЗ  
- Таблица **по тренерам**

Автопроверки: `verify-pnk-stages`, `verify-pnk-coach-notify`, `verify-pnk-client-notify`, `verify-pnk-trainer-glance`, `verify-pnk-manager-board` (в `npm run qa:local` / `agent-qa`).

## Этапы UI ↔ БД

| № | UI | `pnk_stage` / deliverables |
|---|-----|----------------------------|
| 1 | Создан | `new` / `assigned` |
| 2 | Контакт и дата | `contact` → `agreed` + `contact` |
| 3 | Бесплатная | `trial_done` + `trial` (+ nutrition/homework) |
| 4 | Уточнение | `followup` + `followup` |
| 5 | Оформление | `won` → lifecycle `active` / `lost` → `pnk_lost` |

Чеклист: `contact` · `trial` · `nutrition` · `homework` · `followup`.

## Роли

| Роль | Где |
|------|-----|
| Менеджер | `/sales/pnk` — доска, создать, писать тренеру, **удалить ПНК** |
| Админ | `/admin/pnk?club=` — та же доска + карточка клиента + удаление |
| Тренер | Главная (виджет + плитка внимания), фильтр клиентов, 5 шагов в карточке |

Удаление с доски: только карточки в воронке (`pnk` / `pnk_lost`), не оформленный ДК.

npm run db:migrate:pnk -- --linked
