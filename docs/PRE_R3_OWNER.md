## 3. Ночь R3 — чеклист владельца (когда скажете «стартуем R3…»)

Код и скрипты уже в репо (пароли bcrypt→scrypt, runbook волна 3). Ниже — **ваши** шаги; агент ведёт остальное в чате той ночи.

### За сутки / в день до окна

- [ ] Дата окна: ночь **сб/вс** (ориентир), точное время в чат.
- [ ] §1 биллинг ок.
- [ ] §2: нет свежих «опять копирование / абон / Закончить».
- [ ] Свой домен `app.…ru` **или** осознанно временный URL стенда (смена адреса = новые ярлыки PWA).
- [ ] Список «кто знает пароли облака / БД / админ» — у вас в сейфе, не в git.
- [ ] Кто ночью у планшетов клуба (хотя бы один человек).

### В ночь (порядок)

1. [ ] Бэкап prod Supabase (агент подскажет клики / экспорт).
2. [ ] На **всех** планшетах клуба: **Sync** до пустой очереди (иначе pending уедут не туда).
3. [ ] Агент: dump → РФ Postgres, сверка counts (клиенты / тренировки / абонементы).
4. [ ] Пароли сотрудников: выгрузка `auth.users` → скрипт на ВМ (см. [R2_C2_STAGING_RUNBOOK.md](./R2_C2_STAGING_RUNBOOK.md) волна 3) — **сотрудникам пароли не менять**.
5. [ ] DNS / URL приложения → РФ; обновить Auth URL.
6. [ ] Планшеты: новый ярлык PWA, если origin сменился; вход тренера → Закончить → Sync → видно в админке.
7. [ ] 3–7 дней смотреть Sync и статистику; при беде — откат: DNS назад + старый Supabase read-only на окно.

### Не делать в ту же ночь

Оплаты, касса, переписывание Sync, «заодно» крупные фичи CRM, security-спринт §5.7.
