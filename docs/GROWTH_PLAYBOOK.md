# Рост продукта — отчёты и пороги

Вы сообщаете метрики → в чате или здесь в **журнале** — мы делаем оптимизации по приоритету из `DATA_VOLUME.md` и `COMMERCIAL_ROADMAP.md`.  
Платные тарифы: детали перехода в [PAID_TIER_MIGRATION.md](./PAID_TIER_MIGRATION.md).

## Что присылать при росте

| Поле | Пример |
|------|--------|
| Клубов | 1 |
| Тренеров (активных) | 3 |
| Клиентов (всего / на крупнейший клуб) | 120 / 120 |
| Тренировок (крупнейший клуб) | 8 000 |
| Vercel / Supabase план | Hobby / Free |
| Жалобы | «Sync 40 с», «400 на push» |

Опционально: скрин **Supabase → Database → size**, время полного Sync на планшете, число pending в очереди.

## Сейчас в проекте (техника)

- **Vercel:** 12 файлов `api/*.js` — лимит Hobby **исчерпан** (нельзя добавить endpoint без объединения в `admin-data?action=`).
- **Supabase Free:** 500 MB БД, 5 GB egress/мес, 50k MAU, пауза проекта после ~1 недели без активности.
- **Код:** пагинация списка клиентов, архив, pull без архива — см. `CLIENT_ARCHIVE.md`.

## Когда нужны платные подписки (ориентир)

Число **тренеров само по себе** редко упирается в лимит. Важнее: **клубы × объём данных × частота Sync**.

### Vercel Pro (~$20/мес за разработчика с деплоем)

| Причина | Порог (ориентир) |
|---------|------------------|
| **Коммерческое использование** (клуб платит за сервис) | **С первого платного клуба** — по ToS Hobby только для личных проектов |
| Лимит **12 serverless functions** | Уже **12/12** — любой новый `api/*.js` → Pro **или** рефакторинг в существующий handler |
| Таймауты `push-records` / тяжёлый админ API | Очередь >200 pending или batch >60 с на Hobby |
| Много preview/команда | 2+ разработчика с деплоем → ~$40/мес |

**При 1 клубе и 3 тренерах по нагрузке Hobby хватает; по продукту для коммерции разумно закладывать Pro.**

### Supabase Pro (~$25/мес за проект)

| Причина | Порог (ориентир) |
|---------|------------------|
| Размер БД | **>400–500 MB** или рост >50 MB/мес |
| Egress | Стабильно **>4 GB/мес** (много клубов, полный pull на каждом планшете ежедневно) |
| Надёжность | Договор с клубом: **ежедневные бэкапы**, нет паузы после неактивности |
| Пики | `ERR_CONNECTION_RESET`, таймауты в часы пик при 5+ одновременных Sync |
| MAU | Практически не для вас до **сотен** учёток; лимит 50k |

**При 1 клубе и 3 тренерах Free обычно хватает на месяцы и годы**, если в клубе не десятки тысяч тренировок и не тянуть «всё сразу» без фазы 4 (`DATA_VOLUME.md`).

### Сводка: «сколько тренеров до Pro?»

| Ресурс | Условный ориентир |
|--------|-------------------|
| Vercel Pro (нагрузка) | **50–100+** тренеров **и** активный Sync/API — редко упираются раньше лимита функций |
| Vercel Pro (продукт) | **1 коммерческий клуб** → Pro по политике Vercel |
| Supabase Pro (данные) | **1 клуб**, до **~2–5k** клиентов и **&lt;50k** тренировок на Free часто OK |
| Supabase Pro (масштаб) | **5–10+ клубов** на одном проекте **или** **>500 MB** БД **или** нужны бэкапы в договоре |

**Текущая база (1 клуб, 3 тренера):** Supabase Free — норма; Vercel — следить за 12 functions; для коммерции заложить **Vercel Pro $20/мес**, Supabase Pro пока не обязателен.

### Когда в коде (без смены тарифа)

| Сигнал | Действие |
|--------|----------|
| >5k клиентов / клуб | пагинация админки, индексы |
| >20k тренировок / клуб | профилировать pull |
| Pull >30–60 с | фаза 4: pull по периоду (`DATA_VOLUME.md`) |
| >50k тренировок / клуб | фаза 4 + agg на API |
| IDB на планшете >150 MB | окно pull, prune |

## Ориентировочный бюджет «взрослого» продакшена

| Статья | ~$/мес |
|--------|--------|
| Vercel Pro (1 разработчик) | 20 |
| Supabase Pro (1 проект) | 25 |
| **Итого минимум** | **~45** |

Перерасход (egress, compute) на вашем масштабе обычно небольшой, пока мало клубов и нет полного pull гигабайтами.
