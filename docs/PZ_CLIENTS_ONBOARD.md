# Клиенты ПЗ — как завести в Ядро (по шагам)

**Статус:** ✅ lite-ПЗ + связка из вечерних оплат (MVP).  
Массового сида клиентов из «книги часов» **не** делаем: часы дня — Excel `otchet_pz` в отчёте продаж (матрица тренер×тип). Клиенты ПЗ — через оплаты / lite / клип. Авто без выбора тренера — нельзя (в оплатах нет колонки тренера): менеджер выбирает тренера в блоке «Карточки из оплат».

**Не путать с ТЗ/АЗ:** закрытия из 1С → вкладки ТЗ/АЗ **без** живого тренера (`desk_hall`). ПЗ = клиент **с** `trainer_id`. Если клиент ТЗ/АЗ **уже найден** по карте/телефону — новый абонемент **не** создаётся (только skip или проставление `desk_hall`); membership появляется лишь при создании новой desk-карточки.

**Мост → цель:** вечерний `31.xlsx` — переход; целевой контур денег — [PAYMENTS_DOMAIN.md](./PAYMENTS_DOMAIN.md) (**MVP оплат: ПЗ и АЗ**). Карточки из оплат уже создают правду клиента/абона в Ядре. Онбординг АЗ: [AZ_CLIENTS_ONBOARD.md](./AZ_CLIENTS_ONBOARD.md).

---

## Кому это

Админ / менеджер продаж заводит персональный зал в Ядре: часть тренеров пока без планшета — клиентов ведёт админ или менеджер лёгкой карточкой; когда планшет выдали — те же карточки становятся полным дневником.

---

## Шаг 0. Подготовка (один раз на клуб)

1. **Структура → Типы абон.** — типы карт **ПЗ** (для полного дневника на планшете).
2. **Организация → Тренеры** — создать тренеров:
   - клуб, логин, пароль;
   - галка **«Без планшета»** (у нового по умолчанию включена) — админ будет заводить lite-клиентов;
   - снять галку, когда выдали планшет.
3. Кого **не** заводить как тренера: люди без клиентов ПЗ (только зал/админ).

Миграция флага: `npm run db:migrate:users-uses-tablet -- --linked` (колонка `users.uses_tablet`, у текущих = с планшетом).

---

## Вечер: оплаты → отчёт + карточки (переход)

Пока нет домена платежей в БД, ритуал такой. **Цель:** день закрывается из строк оплаты в Ядре, без обязательного файла.

1. **Продажи → Отчёт** — загрузить `31.xlsx` (мост из 1С).
2. Проставить НК/ДК/УК → **Подставить** → **Сохранить** день.
3. В блоке **«Карточки из оплат»** смотрите KPI **«ПЗ без карточки»** (число + сумма):
   - у каждой строки **обязательно** выбрать тренера (без планшета → lite, с планшетом → клип);
   - **Создать** / **Создать готовые** — без тренера кнопка не активна;
   - АЗ/ТЗ ниже — desk (срок: дни или месяцы; «разовое» сразу 1 день; направление АЗ — из тарифа или вручную);
   - если в файле **одна карта и ПЗ, и ТЗ** — обе строки видны; второй зал допишется к той же карточке ([CLIENT_MULTI_HALL.md](./CLIENT_MULTI_HALL.md)).

## Оплата и отчёт (проекция цели) — ПЗ

| Сейчас | Цель для ПЗ |
|--------|-------------|
| Сумма в Excel / форме дня | `payment` с `hall = pz`, сегмент НК/ДК/УК |
| «ПЗ без карточки» → lite / клип | Тот же flow + сохранённый платёж с `client_id` / `membership_id` |
| `paid_amount` на абоне | Цена пакета; не запись кассы |
| Завершение тренировки | Не создаёт платёж |

Подробности канона: [PAYMENTS_DOMAIN.md](./PAYMENTS_DOMAIN.md) §3a.

## Шаг 1. Новый клиент ПЗ с ресепшена (админ / менеджер / управляющий)

1. **Клиенты** (`/admin/clients` или `/sales/clients`) → **«+»** → вкладка **ПЗ** — ФИО, карта, телефон, **любой активный тренер клуба**, даты/пакет абона, цена.  
   В списке тренеров две группы: «Без планшета» и «С планшетом».  
   - **Без планшета** → лёгкая карточка (ведёт админ/менеджер), бейдж «ведёт админ».  
   - **С планшетом** → полный дневник у тренера после Sync (тот же insert `clients` + `memberships`).  
   На вкладках **ТЗ / АЗ** та же кнопка открывает создание desk (без тренера).  
   Если **в этом клубе** уже есть клиент с таким номером карты — создание блокируется с предупреждением (тот же номер в другом клубе — нормально). То же при **смене номера** на lite/desk/карточке тренера и при заявке-клипе (создание / дозаполнение карты).
2. Lite в коммерции:  
   - **В абонах / продлениях / «с действующим» / истекает** — участвуют.  
   - **В «неактивных» и качестве ведения** — нет (пустой дневник не раздувает хвосты).  
   - **Дневной отчёт продаж** — по-прежнему руками (матрица ПЗ); lite сам туда не пишется, но карта и `paid_amount` есть для учёта.

Запись уходит в облако через очередь + flush (как архив / смена тренера).

---

## Шаг 2. Другие способы завести полного ПЗ (тренер с планшетом)

### Заявка тренеру (продажа сегодня)

1. Менеджер: **Продажи → Заявка тренеру**.
2. Тренер: Sync — пакет уже в дневнике.

### Под логином тренера

1. Войти под логином тренера (на любом ПК/планшете клуба).
2. **Клиенты → Новый клиент** — ФИО, телефон, № карты. Карта уникальна **в клубе тренера** (проверка по всем клиентам клуба, не только своим): повтор — предупреждение. Архив с тем же номером тоже блокирует. При правке карты на карточке — тот же контроль.
3. На карточке — абонемент.
4. Sync.

---

## Шаг 3. Когда выдали планшет

1. **Организация** — снять **«Без планшета»** (`uses_tablet = true`).
2. Установить PWA на планшете → войти → **Sync**.
3. Те же клиенты с его `trainer_id` открываются как **полный дневник** (условие lite ложно). Отдельный «апгрейд» строк клиентов не нужен.

Историю занятий **до** планшета Ядро не подтянет сама — она начинается с записей в приложении.

---

## Шаг 4. Если ошиблись с тренером

Админ: **Клиенты** → меню у строки → сменить тренера. Лучше переносить на тренера с тем же режимом планшета.

Уволился: **Организация** → заблокировать → клиентов переназначить.

---

## Чего не делать

| Не так | Почему |
|--------|--------|
| Грузить ПЗ через «Список заканчивающихся» (ТЗ/АЗ) | Там desk без тренера |
| Вешать ПЗ на «Не назначен» | Портит KPI / путаница |
| Создавать тренеров «на всякий» без клиентов | Лишний шум в списках |
| Ждать Excel оплат без выбора тренера | Фаза 2; в `31.xlsx` нет тренера |
