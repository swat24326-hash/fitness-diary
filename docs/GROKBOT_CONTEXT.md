## Канал задач (без владельца)

Папка `bridge/` в корне проекта на ПК владельца (в git не попадает).

- Агент кладёт задачу `bridge/tasks/<id>.md` и будит GrokBot: `node scripts/bridge-wake.mjs <id>` (POST `{"task":"<id>"}` на ссылку из `bridge/webhook.url`, затем ждёт отчёт).
- GrokBot по вебхуку берёт задачи без отчёта, пишет `bridge/reports/<id>.md`. Страховочная проверка папки — 12:00 и 20:00 МСК.
- Ссылка — `bridge/webhook.url`, ключ отправителя — `bridge/webhook.key`, имя заголовка — `bridge/webhook.header` (если не `Authorization: Bearer`). Не в git, не в docs, не в чат.
- Срочное или `danger` — агент просит владельца написать GrokBot в чат.

Задача:

```
id: 2026-09-28-01
risk: read | change | danger
goal: что сделать и зачем
steps: по пунктам, что нажать в консоли
done_when: как понять, что готово
```

Отчёт: `id`, `status: ok | fail | needs_owner`, что сделано, что видно в консоли сейчас, замечания.

## Уровни риска

| Уровень | Примеры | Решение |
|---------|---------|---------|
| `read` | статус ВМ/кластера, логи, список ресурсов, остаток гранта | выполнять сразу |
| `change` | шаги из [R2_C2_STAGING_RUNBOOK.md](./R2_C2_STAGING_RUNBOOK.md) на стенде | выполнять, если шаг есть в runbook |
| `danger` | удаление, новые платные ресурсы, новые ключи/секреты, прод, cutover, биллинг | только после «да» владельца; иначе `needs_owner` |

Секреты (пароли, ключи, `DATABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`) не пишутся в задачи, отчёты, чат и этот файл — только имена переменных.
