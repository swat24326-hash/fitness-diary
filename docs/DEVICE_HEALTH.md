# Центр сбоев устройств

**Статус:** ✅ в проде с 14.10.2026 12:02 МСК (сборка `b12f449`): миграция применена, cron `/etc/cron.d/fitness-diary-device-health` включён.

## Зачем

Планшет тренера ломается тихо: база на устройстве заблокирована старой вкладкой, записи не уходят в облако, сессия истекла, загрузка падает с 502 (INC-2026-10-14-01). Раньше админ узнавал от тренера «приложение не работает» и разбирал по фото. Теперь планшет сам сообщает о серьёзном сбое, админ получает push и видит, **что сказать тренеру**.

## Кто что видит

| Кто | Где | Что |
|---|---|---|
| Админ сети | иконка «Сбои устройств» в шапке (рядом с конвертом) → `/admin/health` | число планшетов в сбое (красное — критичный). Карточки «Требуют внимания»: что сломалось, «Не уходит с планшета» (текст отказа). Одинаковый текст отказа на нескольких планшетах — одна карточка, написать и «Решено» у каждого тренера. Ниже «Все устройства» по-прежнему по одному; свёрнуто «Это устройство» (бывшая «Структура → Диагностика») |
| Тренер | иконка «Помощь» в шапке — **только при сбое** | открывает «Помощь», сверху — что не так и что сделать |
| Админ (push) | уведомление «Сбой планшета: ФИО» | сразу при новом критичном сбое; повтор не чаще раза в 2 ч, днём 8–22, пока планшет на связи и не нажато «Решено» |

## Коды

Один каталог — `src/lib/deviceHealth/deviceHealthCatalog.js` (тексты для админа, тренера и push).

| Код | Кто ставит | Когда | Push |
|---|---|---|---|
| `db_blocked` | планшет | база на устройстве не открывается (старая вкладка держит обновление) | да |
| `auth_stuck` | планшет | в очереди ошибка сессии (401) | да |
| `queue_stuck` | планшет | запись в очереди старше 30 мин после попыток отправки, сеть есть | да |
| `pull_failing` | планшет | загрузка данных (trainer-pull) падает 30+ мин, ≥2 попытки подряд | нет |
| `build_stale` | планшет | на сервере другая сборка 3+ ч | нет |
| `server_no_pull` | сервер (cron) | планшет на связи и видит `pull_failing`, а сервер 2+ ч не видел успешной загрузки с него; только 7–23 МСК | да |

Загрузка с сервера идёт по Sync и при открытии списка клиентов, не по таймеру — поэтому «давно не грузил» само по себе не сбой.

## Как устроено

- **Планшет:** `deviceHealthReporter.js` (запуск из `App.jsx` для роли тренера) — проверка раз в 5 мин и при возврате сети/экрана; отчёт `POST admin-data?action=device-health` при смене набора проблем и раз в 30 мин «на связи», только на экране и с сетью. Если в очереди есть отказ, в тот же отчёт кладётся до 5 коротких строк (`queue_lines`: таблица, действие, имя, попытки, текст ошибки) — без тела записи. Новый текст уходит на следующей проверке, не через полчаса. Очередь не прочиталась — прошлый текст на сервере не затирается. IndexedDB ждёт ≤3 с и не пишет туда; отметки — в localStorage (`deviceHealthMarks.js`). Правила — `deviceHealthSignalsCore.js`, строки очереди — `deviceHealthQueueCore.js`.
- **Сервер:** таблица `device_health` (одна строка на тренера + устройство, RLS закрыт); `problems` — от планшета, `server_problems` — от cron. `trainer-pull` после успеха пишет `last_pull_ok_at` по `x-device-id` (без ожидания). Правила — `api/_lib/deviceHealth/deviceHealthCore.js`, API — `deviceHealthHandler.js`, cron — `deviceHealthJob.js`.
- **«Решено»** прячет карточку, пока набор проблем не расширился; всё прошло — отметки сбрасываются. Сутки без отчётов — проблемы снимаются (планшет выключен), строка остаётся в «Все устройства».

Проверки: `scripts/verify-device-health.mjs`, автотест экрана «центр сбоев устройств» (`scripts/e2e/scenarios/deviceHealth.mjs`).
