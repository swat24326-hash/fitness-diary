# Приложение тренера на телефоне (`/coach`)

**Актуально:** 2026-10-11  
**Статус:** поставка A — ✅ в проде с 11.10.2026 (коммит `7ac83fe`, миграция `20261012120000_coach_app.sql` применена); 👀 пилот на 1–2 тренерах. Поставка B (задачи «Планёрки», напоминания об абонементах) — 📋 после отзывов пилота.

## Ситуация

Клиент пишет тренеру в приложении клуба (`/me`, [CHAT.md](./CHAT.md)), а планшет лежит в зале. Тренер узнаёт о сообщении только у планшета — и отвечает в личный мессенджер, мимо клуба. На телефоне ему нужны две вещи: ответить клиенту и посмотреть, кто у него сегодня и завтра.

**К цели:** общение остаётся в CRM клуба, а не в личной переписке. Телефон — окно в Ядро, а не второй планшет: без офлайна, без тренировок и без данных клиентов на устройстве.

## Как пользоваться

**Тренер, проще всего — QR:** на планшете меню (☰) → «Настройки» → «QR для телефона» → навести камеру телефона на код. Откроется приложение тренера без пароля; дальше, как и при входе по паролю, телефон ждёт «Разрешить». Код одноразовый, живёт 10 минут; закрыть браузер, пока ждёт админа, можно — при следующем открытии `/coach` ожидание продолжится.

**Тренер, по паролю:** открыть на телефоне `https://app-core.ru/coach` → логин и пароль те же, что на планшете. Первый вход с телефона ждёт администратора («Телефон ждёт разрешения»); экран сам проверяет каждые 15 с и входит после «Разрешить». **Значок «Домой»:** на iPhone в Safari после входа над Ежедневником есть подсказка в одну строку, шаги по «Как?» — «Поделиться» → «На экран „Домой“» → открыть значок с названием клуба. Значок входит сам и не просит админа разрешить ещё раз; ставить значок, **пока подсказка на экране** (после «Готово» значок откроется со входом по паролю или QR). Значок, поставленный до 11.10, — удалить и поставить заново (INC-2026-10-11-02). На Android значок тоже называется как клуб. В шапке — название клуба; без клуба приложение — «Результат Плюс · тренер», знак пока Ядра ([BRAND_SYSTEM.md](./BRAND_SYSTEM.md) §0). Если тренер раньше входил с этого телефона в обычное приложение и по ссылке открылась главная тренера — открыть `/coach` ещё раз: в первый раз обновилась сохранённая версия (INC-2026-10-11-01).

- «Ежедневник» (📋 в коде, ждёт выкатки) — главный экран, приложение открывается на нём (отдельного экрана «Сегодня» больше нет, решение владельца 11.10). Тот же календарь, что на планшете: День / 3 дня / Месяц, создать, изменить, удалить, повторять каждую неделю, перенести пальцем с «Отменить». Сохраняется сразу на сервер; на планшете появится после Sync. Если запись успели поменять на планшете — «Запись изменилась на планшете — обновите Ежедневник», правка планшета не затирается. Начать тренировку с телефона нельзя — только на планшете. Подробно — [TRAINER_SCHEDULE.md](./TRAINER_SCHEDULE.md) фаза 2e.
- «Сообщения» — диалоги «Тренер» своих клиентов; ответ уходит клиенту так же, как с планшета. Ждут ответа — красное число на вкладке (`useCoachAttention.js`).
- «Меню» — три полоски справа в шапке (внизу только «Ежедневник» и «Сообщения»): «Обновить» (перезагрузка; Ежедневник и сам подтягивает правки планшета, когда тренер возвращается в приложение), уведомления о сообщениях (push открывает сам диалог на телефоне) и «Выйти».

**Админ:** «Устройства тренеров» (`/admin/devices`) — телефон помечен значком телефона. У тренера одно разрешённое устройство каждого вида: планшет и телефон не мешают друг другу. «Разрешить» новый телефон — прежний телефон тренера сразу теряет вход; кнопки «Заменить» у телефона нет. Потерян телефон — «Отозвать». Шаги — [RUNBOOK.md §4e](./RUNBOOK.md).

## Правила

- Только роль «тренер», активный пользователь. Блок тренера, смена пароля, «Отозвать» телефон — следующий запрос телефона выкидывает на вход с объяснением.
- Каждый новый или отозванный телефон ждёт админа, даже первый и даже при выключенной привязке планшетов (`DEVICE_BINDING_SINCE`).
- Пропуск телефона (`typ: coach`) не принимается API планшета, `/rest/v1` и приложением клиента; пропуск планшета не принимается `/api/coach`.
- На телефон уходят белые списки: имя тренера, записи своего Ежедневника (с текстом заметки), имена своих активных клиентов, статус тренировки по записи, переписка «Тренер». Без телефонов клиентов, карт, данных тренировок и денег.
- Правка Ежедневника с телефона проходит те же серверные проверки, что запись с планшета (`authorizePush`): только свои клиенты, свой клуб; запись с тренировкой переносится по правилу планшета.
- Нет сети — «Нет сети — данные на телефоне не хранятся». Очередь sync и IndexedDB не используются.

## Как устроено

- Вид устройства — в номере: телефон получает `coach-…` (`src/lib/coach/coachSession.js`), поэтому правила планшетов в `api/_lib/deviceBindingCore.js` телефоны не видят, а `decideCoachDevice` решает только за телефоны. Новых колонок в `user_devices` / `auth_sessions` нет.
- Вход и продление: `/api/coach-auth` → `api/_lib/coach/coachAuthHandler.js` (тот же лимит неудачных входов, что у `/api/auth-sign-in`), токены — `coachAuthCore.js`, сессия в `auth_sessions` с `device_id = coach-…`. Каждый запрос `/api/coach` проверяет пользователя, сессию и разрешение телефона (`requireCoachUser.js`); любой отказ — 401.
- QR: планшет (бургер → «Настройки», `src/components/header/HeaderSettingsMenu.jsx` → `HeaderSettingsModals.jsx` → `CoachPhoneQrModal.jsx`, окно порталом в `body`) берёт код `coach-auth { action: 'invite' }` со своим входом; ссылка `/coach/join#t=…` (`src/lib/coach/coachJoinLink.js`) — код в #, не в логах сервера; телефон сразу сохраняет код и убирает его из адреса (`CoachAppRoutes.jsx` → `CoachJoinPage.jsx`). Сервер — `coachInviteHandler.js` + `coachInviteCore.js`, в базе только отпечаток кода (`coach_invites`). Пускать ли телефон, решает тот же `admitCoachPhone`, что и при пароле.
- Данные: `/api/coach` → `coachHandler.js`; `view=schedule` (сегодня/завтра, `coachViewCore.js`) остался для телефонов со старой версией, новый экран его не зовёт; Ежедневник — `coachScheduleHandler.js` (чтение периода) + `coachScheduleWriteCore.js` (запись через `executePushRecord`); переписка — те же `handleStaffChatGet/Post`, что у планшета, только диалог «Тренер».
- Push: колонка `user_push_subscriptions.app` (`staff` | `coach`). Подписка с телефона — `coach`; при отправке ссылка переписывается под приложение (`src/lib/push/pushTargetUrlCore.js`): диалог «Тренер» → `/coach/chat/:clientId`, остальное → `/coach`.
- Значок iPhone: у значка своё хранилище, не как у Safari. Пока видна подсказка (`CoachInstallBanner.jsx` → `useCoachHandoff.js`), Safari берёт `/api/coach { op: 'handoff' }` и держит в адресе `/coach?h=…` — iPhone запоминает его для значка (manifest на iPhone не ставим). Значок без входа с `?h=` → `coach-auth { action: 'handoff' }` (`CoachAppRoutes.jsx`, `CoachJoinPage.jsx` kind=`handoff`) и берёт номер телефона из приглашения. Сервер — `coachHandoffHandler.js`. Название клуба: `view=me` → `club`, хранится на телефоне (`coachSession.js`), `CoachShell.jsx` → `useClientBranding`; manifest Android — `/api/coach?manifest=` (`coachManifestCore.js`).
- Экраны: `src/pages/coach/` (вход, «Ежедневник» = `/coach`, «Сообщения», диалог, «Меню» = `/coach/more`; старый адрес `/coach/calendar` ведёт на `/coach`), стили `src/styles/coach.css` и `coach-schedule.css`, manifest `public/manifest-coach.json`.
- Проверки: `verify-coach-auth.mjs`, `verify-coach-app.mjs`, `verify-coach-schedule-edit.mjs`; экран — сценарии «телефон тренера» и «Ежедневник с правкой» в `npm run qa:screens`.
