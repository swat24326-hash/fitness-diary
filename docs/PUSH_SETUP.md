# Push Планёрки — чеклист перед продом

Офлайн-тренировки **не зависят** от push. Без ключей задания работают через виджет и шапку.

Те же VAPID-ключи шлют напоминания клиентам о тренировке (приложение `/me`): своя таблица подписок и cron на ВМ — [CLIENT_APP.md](./CLIENT_APP.md) § «Уведомления клиенту».

Тренеру по тем же подпискам приходят напоминания за 15 минут до записи Ежедневника (выключатель на устройстве, cron на ВМ каждые 5 минут) — [TRAINER_SCHEDULE.md](./TRAINER_SCHEDULE.md) § «Фаза 2f».

## 1. Миграция Supabase

```bash
npm run db:migrate:iskra -- --linked
```

Проверяет в том числе таблицу `user_push_subscriptions`.

## 2. VAPID-ключи

**Сейчас (ВМ, app-core.ru):** `sudo bash scripts/push-vapid-setup-vm.sh` — генерирует ключи прямо в `/opt/fitness-diary/.env`, ничего не печатает, рабочие ключи не трогает (`--force` — сменить; тогда все подписки надо включить заново). Затем `sudo bash scripts/r3-deploy-vm.sh origin/main` — публичный ключ попадает в сборку. Заглушка вместо ключа сервер считает «не настроено» (INC-2026-10-07-05).

**Старый путь (Vercel, до 01.10.2026):**

```bash
npx web-push generate-vapid-keys
```

В **Vercel → Settings → Environment Variables** (Production):

| Переменная | Значение |
|------------|----------|
| `VAPID_PUBLIC_KEY` | public из команды выше |
| `VAPID_PRIVATE_KEY` | private (не в git, не VITE_) |
| `VAPID_SUBJECT` | `mailto:ваш@email.ru` |

Опционально для сборки фронта: `VITE_VAPID_PUBLIC_KEY` = тот же public.

После добавления — **Redeploy**.

## 4. Проверка на планшете

1. PWA на домашнем экране (iOS — обязательно для push).
2. Любой сотрудник (тренер, менеджер продаж, управляющий, главный админ) → меню → своё имя → **«Мой профиль»** → **«Уведомления»**. «Проверить» / «Переподключить» — меню ☰ → **Помощь** (у админа — **Журнал ошибок**) → блок «Уведомления».
3. **Проверить** — тестовое уведомление: тренеру и продажам ведёт во входящие Планёрки, админу и управляющему — в «Сообщения» (`staffPushTestUrl` в `pushTargetUrlCore.js`).
4. Админ / менеджер → Планёрка → поставить задание → push на устройство исполнителя.
5. Тап по уведомлению → открывается Планёрка (`?inbox=1`).

GET `admin-data?action=push-subscription` доступен ролям `admin`, `trainer`, `sales_manager`, `supervisor` (публичный VAPID-ключ для подписки).

Что приходит главному админу: новое личное сообщение от сотрудника (тап — диалог в мессенджере `/messages?dm=…`), новое устройство тренера ждёт разрешения, статус задания, которое он отправил, **«Сбой планшета»** — серьёзная проблема у тренера (тап — `/admin/health`; повтор не чаще раза в 2 ч и только 08–22 МСК, cron `device-health-vm.sh` — [DEVICE_HEALTH.md](./DEVICE_HEALTH.md)).

## 5. Если push не пришёл

- Нет VAPID на Vercel → задания всё равно в приложении.
- Не дали разрешение браузеру.
- iOS без «На экран Домой».
- Тренер не нажал «Включить» в профиле.
- Серый текст «Включены», красный при «Проверить» → рассинхрон браузер/сервер: **Переподключить**, затем снова **Проверить**.
- Телефон заблокирован: сервер шлёт все push срочными (`urgency: high`, `src/lib/push/webPushDelivery.js`) — Android в режиме сна отдаёт сразу. Задержки остаются от энергосбережения и «усыпления» браузера оболочкой (Xiaomi, Huawei, Samsung — разрешить браузеру работу в фоне). «Не беспокоить» / «Фокусирование» — уведомление пришло, но без баннера и звука.
- Телефон без сети дольше 3 суток — старые push не приходят (TTL), сообщения видны в приложении.
- **Самовосстановление подписки** (`src/lib/push/pushSelfHeal.js`, правила — `pushSelfHealCore.js`): при открытии приложения и возврате в него (не чаще раза в 30 мин) телефон, где уведомления включены и разрешены, молча передаёт свою подписку серверу, а пропавшую оформляет заново. Закрывает «телефон пишет „включены“, а не приходит» — iPhone меняет / теряет подписку, сервер удаляет протухший адрес. Кто выключил уведомления сам — обратно не включаем (отметка `fd_push_on:<app>` на устройстве). iOS не дал оформить без касания — экран покажет «Включить». Подключено: шапка зала (`useStaffPushSelfHeal`), телефон тренера (`CoachShell`), клиент (`useClientPush`).
- iPhone в принципе: iOS 16.4+, приложение на экране «Домой», уведомления включены изнутри установленного приложения; во вкладке Safari push нет.

## 6. Microsoft Edge (ошибка «push service error»)

1. **Windows:** Параметры → Система → Уведомления → **Microsoft Edge** — включено.
2. **Edge:** `edge://settings/content/notifications` — сайт `fitness-diary-bice.vercel.app` в «Разрешить».
3. Закройте **InPrivate** и корпоративный VPN (блокируют WNS).
4. Обновите страницу (Ctrl+F5) и нажмите **Включить** снова.
5. Если не помогло — проверьте VAPID в Vercel (`npx web-push generate-vapid-keys`, redeploy).
6. Временный обход: **Chrome** на том же ПК — push там обычно стабильнее.
