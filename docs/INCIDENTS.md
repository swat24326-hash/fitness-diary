## 1. Контуры (кто сообщил)

| Контур | Кто / где | Типичный вход |
|--------|-----------|---------------|
| **зал** | Тренер, планшет, PWA | «пропало», «не сохранилось», Sync |
| **админ** | Админ, управляющий | статистика, карточка, ИСКРА, структура |
| **продажи** | Менеджер `/sales` | отчёт, ПНК, ЗП, акции |
| **связь** | Админ / менеджер | SMS, звонки, Max, журнал связи |
| **инфра** | Любой + разработчик | вход, деплой, Supabase, клуб ≠ облако |

Один инцидент → **один контур** + **один код направления** (ниже). Если симптом на стыке (например Sync + пустая карточка) — код **первопричины** (часто `C` или `D`, не оба).

## 7. Алгоритм для агента (кратко)

Полный чеклист: `.cursor/rules/fitness-diary-incidents.mdc`.

1. **Симптом в чате** → открыть этот файл, найти похожую строку в §5 (grep по ключевым словам).
2. **Контур + код** из §1–2; при сомнении — код **первопричины**.
3. **Повтор** → обновить статус существующего INC; **новый** → INC-ID + строка в §5 + §6 если нетривиально.
4. **Разбор** → root cause; фикс по `fitness-diary-stability.mdc` / `fitness-diary-fix-comprehensive.mdc`.
5. **После фикса:** статус → 🔧/🚀; `CHANGELOG` если UX; verify; CRITICAL если критический путь.
6. **RUNBOOK** — только если нужна **новая** пошаговая инструкция для зала (не дублировать историю кейса).
7. **Закрытие** → ✅ после деплоя и отсутствия повтора; редкие → 👀 watch.
