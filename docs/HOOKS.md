# Хуки Cursor — автоматические тормоза

**Актуально:** 2026-09-29
**Для кого:** владелец (что вы увидите и как отключить) и агент (что уже проверяется само).

## Зачем это

Три ситуации, которые раньше держались только на честном слове агента:

1. Агент «помогает» и сам делает `git reset`, миграцию базы или `rm -rf` — можно затереть работу или прод-данные.
2. Вы вставляете в чат ключ из консоли Supabase, чтобы агент разобрался — боевой `service_role` уезжает в модель и остаётся в истории.
3. Правка сделана, `npm run lint` забыт — ошибка уезжает в репозиторий.

«Заливай» в чате — это уже согласие на коммит, push и деплой. Хук на этих трёх командах **не** спрашивает повторно.

Хуки — маленькие скрипты, которые Cursor запускает **вокруг** действий агента. Правила (`.cursor/rules/`) объясняют, как надо; хуки не дают сделать иначе.

## Что стоит

| Хук | Когда срабатывает | Что делает |
|-----|-------------------|------------|
| `guard-shell.mjs` | Перед любой командой в терминале | Спрашивает подтверждение на опасное: `git merge` / `reset` / `clean` / `revert` / `checkout` / `restore` / `rebase`, `git push --force`, `git branch -D`, `git stash clear/drop`, `gh pr`, миграции базы (`db:migrate`, `apply-*`, `supabase db/migration`, `psql`), прод-QA (`qa`, `qa:roles`, `qa:deep`, `agent-qa.mjs` без `--skip-prod`), рекурсивное удаление (`rm -r`, `Remove-Item -Recurse`, `rd /s`, `del /s`), `vercel env rm`, любые команды с `.env` (кроме `.env.example`). Понимает цепочки `&&`, `;`, `|`, `&` и перенос строки. Обычные коммит, push и `vercel --prod` пропускает молча — владелец уже сказал «заливай» |
| `guard-prompt-secrets.mjs` | Когда вы нажали «отправить» | Отменяет отправку, если в сообщении боевой секрет: JWT с ролью `service_role`, `sb_secret_`, `SERVICE_ROLE=…`, ключ Gemini/Google, пароль в строке подключения `postgres://`, токен Telegram-бота, ключ Yandex Cloud. Обычный `anon` ключ, чтение `process.env.…` в коде и заглушки вида `your-…-here` секретом не считаются |
| `guard-read-secrets.mjs` | Перед чтением файла моделью | Не даёт прочитать `.env` (кроме `.env.example`) и любой файл, где нашёлся такой ключ |
| `track-edit.mjs` | После каждой правки файла | Просто запоминает путь в `.cursor/hooks/.state/` (в git не попадает) |
| `stop-check.mjs` | Когда агент закончил ответ | Гоняет eslint **только по изменённым** файлам; при ошибках сам просит агента исправить. Если тронут критический путь (sync, абонементы, agg) — напоминает про `npm run qa:critical` |

Настройка — [`.cursor/hooks.json`](../.cursor/hooks.json), код — `.cursor/hooks/*.mjs`, общая логика — `.cursor/hooks/lib/`.

## Что вы увидите

- **Карточка подтверждения** с текстом «Подтвердите команду: …» — это `guard-shell`. Нажали «разрешить» — команда идёт дальше.
- **Отменённая отправка сообщения** с текстом про найденный секрет — уберите ключ из текста. Если ключ уже был отправлен раньше, его надо **сменить** в Supabase / Vercel: считайте засвеченным.
- **Агент сам продолжает работу** после «готово» — значит `stop-check` нашёл ошибки eslint или критический путь без QA.

## Границы

- Хуки **не заменяют** `npm run lint` и `qa:critical` перед «готово» — они ловят забытое.
- Напоминание от `stop-check` — это ещё один запрос агента (то есть расход лимита). Про критический путь оно приходит не больше одного раза на каждый ответ агента, про ошибки eslint — не больше двух кругов на ответ (`loop_limit: 2` в `hooks.json`). В длинном чате с многими ответами напоминаний может быть больше двух.
- Cursor на Windows отдаёт хукам путь с кириллицей испорченным (`разработка` → `СЂР°Р·…`). `stop-check` восстанавливает такой путь (`lib/pathEncoding.mjs`); без этого eslint после ответа молча не запускался.
- Тестовые образцы ключей в `scripts/verify-hooks-guards.mjs` собираются склейкой строк — так агент может читать тест. `scripts/verify-hooks.mjs` хранит образцы целиком, поэтому агенту его читать и править нельзя: новые кейсы — в `verify-hooks-guards.mjs`.
- MCP-серверы в проекте не подключены. Новый — только с ключами через env (не в конфиге) и без записи в прод-базу.
- При поломке (нет node, сбой скрипта) хуки **пропускают** действие, а не блокируют работу: терминал и чат не должны «кирпичиться». Значит это страховка, а не защита от злого умысла.
- Слово «заливай» в чате — разрешение на весь цикл. Без этой просьбы агент сам не коммитит и не деплоит (`fitness-diary-ship.mdc`).

## Изменить или выключить

1. Открыть `.cursor/hooks.json` и удалить нужный блок (например `beforeSubmitPrompt`) — Cursor подхватит файл сам, перезапуск не нужен.
2. Что именно спрашивать — списки в `.cursor/hooks/lib/shellGuardRules.mjs`, секреты — `lib/secretScan.mjs`, критический путь — `lib/stopCheckRules.mjs`.
3. После правки этих списков: `node scripts/verify-hooks.mjs`, `node scripts/verify-hooks-guards.mjs` и `npm run lint:hooks` (оба входят в `npm run qa:local`; обычный `eslint .` в папки с точкой не заходит).
4. Загрузились ли хуки, видно в настройках Cursor → вкладка **Hooks**.
