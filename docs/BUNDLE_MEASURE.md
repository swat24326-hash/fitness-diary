## Из чего main (ранжирование по «весу» модуля до финального minify)

Доли — от суммы вкладов модулей в отчёте visualizer (они больше файла на диске; **порядок важнее точных %**).

### Крупные npm-пакеты

| Пакет | Зачем в продукте | Оценка вклада |
|-------|------------------|---------------|
| **xlsx** | Excel импорт/экспорт (продажи, прайс, закрытия) | ~13% — **самый жирный лишний груз для тренера** |
| **react-dom** | UI | ~8% — норма |
| **chart.js** | графики статистики / ИСКРА | ~5–6% |
| **@supabase/** (auth + postgrest + storage + realtime…) | облако | ~10% суммарно |
| react-router, lucide-react | маршруты, иконки | умеренно |

### Наш код (крупные зоны)

| Зона | Оценка | Комментарий |
|------|--------|-------------|
| `src/lib/admin` | ~13% | много сервисов продаж/статистики в общем бандле |
| `src/pages/admin` | ~8% | толстые страницы (Clients, Sales, Organization…) |
| `src/pages/trainer` | ~4% | карточка, тренировка, питание |
| `src/lib/priceList` + компоненты прайса | ~4% | тянут xlsx статически |
| `src/components/admin` / iskra / trainer | понемногу | |

Крупные одиночные файлы приложения: `AdminClients.jsx`, `AdminOrganization.jsx`, `AdminSales.jsx`, `TrainingForm.jsx`, `MembershipManager.jsx`, `ClientNutritionPage.jsx`.

## Вывод простыми словами

1. **Да, main ~2,9 MB большой** для первого захода планшета; по сети после сжатия ~0,85 MB JS + CSS/шрифты.
2. Главная причина не «План ЗП», а **всё в одном чанке**: админка + Excel (`xlsx`) + графики грузятся и тренеру.
3. Уже хорошо вынесено lazy только **ИСКРА-панель** (`GeminiAnalyticsPanel`).
4. Самый выгодный следующий шаг *когда решите резать* (не сейчас без dig):  
   - lazy `xlsx` / прайс / Excel-импорты продаж;  
   - lazy тяжёлые admin-страницы с маршрута;  
   - при необходимости — `chart.js` только со статистики.

Повторить замер: `npx vite-bundle-visualizer --template list --open false` и разобрать `stats.yml` из temp.
