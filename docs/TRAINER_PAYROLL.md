# ЗП тренеров (план, ставки, прогноз)

**Актуально:** 2026-09-08
**Статус:** ✅ в проде — план уровней, ставки на типах карт, кабинет тренера, снимок прошлого месяца, прогнозы дня / периода / месяца.

## Ситуация → польза

Клуб платит тренеру за проведённые персональные тренировки, но ставка зависит от объёма месяца: чем больше тренировок, тем выше уровень. Раньше это считали руками в Excel. Теперь цифра одна и та же в дневном отчёте, статистике по типам карт, прогнозе чистой прибыли и в кабинете самого тренера.

## Где в UI

| Что | Где |
|-----|-----|
| Пороги тренировок месяца → уровни 2 и 3 | **Структура → План ЗП** (клуб) |
| Ставки ₽ уровней 1–3 и галочка **«В план»** | **Типы абон.** (`trainer_pay_l1/l2/l3`, `counts_toward_pay_plan`) |
| Кабинет сотрудника: с планом / без плана, ±₽ за тренировку | **Структура → Тренеры → кабинет** (иконка кошелька) |
| Колонки «База» и «Итого ЗП» | Дневной отчёт продаж и статистика «тренировки по типам карт» |
| Своя ЗП тренера | Кабинет тренера (по своему журналу завершённых тренировок) |

## Модель

- **Пороги — про количество, ставки — про деньги.** В настройках клуба лежат только `workouts_l2_min` / `workouts_l3_min` (`trainerPayPlanCore.js`); рубли живут на типе карты (`trainerPayTiersCore.js`). Старые ключи `hours_l2_min` / `hours_l3_min` читаются для совместимости.
- **Уровень.** Без плана — всегда уровень 3. С планом — по числу тренировок **календарного** месяца (`resolveTrainerPayLevel`).
- **Что двигает план.** Только карты с галочкой «В план» и оплатой больше 0 ₽. «Без типа» и типы со ставкой 0 план не двигают (`sumWorkoutsByTrainerFromMatrixRows`). Если флага нет в старом кэше или снимке — фолбэк «ставка > 0» (`membershipTypeCountsTowardPayPlan`).
- **Надбавка кабинета.** ±₽ за тренировку применяется к ставке уровня и не уводит её ниже нуля. Карта с оплатой 0 ₽ надбавку **не** получает — нулевую ставку нельзя «накрутить» (`effectiveSessionRate`).
- **Аэробный зал — отдельно:** количество по типу × `aerobic_pay_amount` (`aerobicPayrollCore.js`), в пороги плана ПЗ не входит.

## Снимок месяца

Прошлый календарный месяц считается по **замороженным правилам** (`club_trainer_pay_month_snapshots`): ставки типов, пороги плана и кабинеты на тот момент. Текущий месяц — live. Логика: `trainerPayMonthSnapshotCore.js` (`shouldFreezePayMonth`, `payrollOptsFromSnapshot`), на сервере — `api/_lib/trainerPayrollContext.js`. Смысл простой: поднятая сегодня ставка не должна переписывать уже выплаченный май. Снимки, сделанные до фикса АЗ, не хранили `aerobic_pay_amount` — он подставляется из live (`enrichPaySnapshotMembershipTypesForAerobic`).

## Прогнозы (три разных, не путать)

| Прогноз | Файл | Смысл |
|---------|------|-------|
| День | `trainerDayPayrollForecastCore.js` | База по ставкам уровня + итого с надбавкой; без плана — сценарии уровней 1/2/3 в ячейке |
| Период | `trainerPeriodPayrollForecastCore.js` | По таблице «тренировки по типам карт»; объём достраивается до конца периода (`projectWorkoutsToPeriodEnd`) |
| Месяц (для чистой прибыли) | `trainerMonthPayrollForecastCore.js` | **Прогнозный** уровень × прогноз часов × микс типов + надбавка. Не замороженная средняя MTD |

Чистая прибыль клуба: `computeNetProfitWithPayroll` (выручка − ЗП ПЗ − расходы − ЗП АЗ).

## API

`admin-data?action=trainer-pay-plan-settings` и `trainer-pay-profiles`: GET — админ, менеджер и управляющий своего клуба; POST — только админ. Контекст расчёта на сервере — `trainerPayPayrollContextHandler.js`. Подробности — [API.md](./API.md).
