# Качество ведения тренера

**Статус:** ✅ в коде (MVP, 2026-07)  
**Кому:** управляющий (статистика клуба) и тренер (своя статистика) — **одни правила**.

## Зачем

Не судим за списание занятия. Смотрим:

1. **Ведение** активных клиентов (рацион после смены веса, обмеры где уместно).
2. **Глубина** дневника (не тонкая запись «на закрытие»).
3. **Хвосты базы** в «Неактивных»: ДК и после **БЗ** — либо новый абонемент / оформление, либо отказ, либо архив.

На карточке видно **направление просадки** (куда смотреть), не один непрозрачный %.

## Цифры

| Правило | Значение |
|---------|----------|
| Период | выбранный в статистике (обычно 30 дней) |
| Активный клиент | ≥1 completed у тренера за период |
| Рацион F1 | план есть и stale **> 7** дней после смены веса/роста |
| Обмеры F2 | нет замера за период, если цель на тело **или** обмеры уже вели |
| Тонкая тренировка | 1 упражнение с данными **или** ≤2 set-строк |
| Неактивные | 0–7 коридор · 8–14 внимание · **>14** stuck (без архива) |
| После БЗ | то же; исход: ДК / отказ ПНК / архив |
| Мало данных | &lt;8 completed или &lt;3 активных — care/depth не сравниваем; stuck всё равно |

Статусы: **Ок** / **Внимание** / **Разбор** / **Мало данных**.  
`stuck ≥ 1` → не «Ок» (обычно «Разбор»).

## Где в UI

- Админ: **Статистика клуба** → блок «Качество ведения» (сводка по тренерам + клик → оси просадки и факты). В рейтинге по завершённым — чип статуса и направление просадки.
- Тренер: **Статистика** (тот же `AdminClubStatsSection` в trainer scope) → «Ваша оценка» + те же правила («Как считается»).
- В фактах имя клиента — ссылка на карточку (`/admin/clients/:id` или `/trainer/clients/:id`).

## Код

| Файл | Роль |
|------|------|
| `src/lib/admin/coachQualityCore.js` | правила, статусы, подписи осей |
| `src/lib/admin/coachQualityAgg.js` | агрегат byTrainer |
| `src/lib/admin/coachQualityService.js` | загрузка health/обмеров/веса (локальный/тренерский scope) |
| `api/_lib/adminData/clubHandlers.js` | `club-stats` → `coachQuality` по тем же trainings, что сводка клуба |
| `src/components/CoachQualityPanel.jsx` | UI |
| `scripts/verify-coach-quality.mjs` | verify |

Подключение: `buildScopePeriodStats`, `loadClubTrainingStats` → поле `coachQuality`.  
Админская сводка клуба берёт `coachQuality` из **`admin-data?action=club-stats`** (service role), чтобы не зависеть от пустого IndexedDB и RLS браузера.

## Проверка

```bash
node scripts/verify-coach-quality.mjs
```

Входит в `npm run qa:local` через `agent-qa.mjs`.

Набор покрывает:

| Блок | Что проверяет |
|------|----------------|
| **TECH** | тонкая/глубокая запись, F1/F2, коридор неактивных 0–7 / 8–14 / >14, БЗ/архив/won, статусы и оси просадки, индексы обмеров/веса |
| **COACH** | конвейер тонких, stale-рацион, обмеры только где уместно, хвост→архив, хвост после БЗ, мало данных без ложного минуса за списание |
| **MANAGER** | два тренера (объём vs качество), сортировка «разбор» сверху, фильтр одного тренера, медиана клуба, равный объём разное ведение |

Ручной смоук: статистика админа и тренера → блок «Качество ведения» → просадка + факт → ссылка на клиента.

## Не в этом MVP

- Минус за отсутствие записи звонка (outreach).
- Привязка к ЗП / публичный рейтинг.
- ИСКРА как часть индекса.
- % оформлений ПНК внутри care (продажи — отдельный контур).
