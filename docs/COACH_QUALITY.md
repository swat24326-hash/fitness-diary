# Качество ведения тренера

**Статус:** ✅ в коде (MVP, 2026-07)  
**Кому:** управляющий (статистика клуба) и тренер (своя статистика) — **одни правила**.

## Зачем

Не судим за списание занятия. Смотрим:

1. **Ведение** активных клиентов (заполненная карта здоровья, рацион при работе с весом, обмеры где уместно).
2. **Глубина** дневника (не тонкая запись «на закрытие»).
3. **Хвосты базы** в «Неактивных»: ДК и после **БЗ** — либо новый абонемент / оформление, либо отказ, либо архив.

На карточке видно **направление просадки** (куда смотреть), не один непрозрачный %.

## Как считаются доли

1. **Оси** (ведение / глубина / хвосты) — веса в итоге, сумма 100%.
2. **Внутри ведения** — паспорт, нет рациона, устаревший рацион, обмеры делят 100% между включёнными (дефолт 25/25/25/25). Урон по клиенту = сумма долей сработавших пунктов (макс. 100).
3. **Глубина** — один тумблер «тонкие»; доли внутри оси нет.
4. **Внутри хвостов** — stuck ДК / stuck БЗ / коридор 8–14 (дефолт 40/40/20). Потолок балла 79 — отдельный тумблер, не доля.
5. Выключенный пункт не участвует; его % перераспределяется на включённые при сохранении.

## Цифры

| Правило | Значение |
|---------|----------|
| Период | выбранный в статистике (обычно 30 дней) |
| Активный клиент | ≥1 completed у тренера за период |
| Рацион F1 | нет плана при цели на вес/форму или если вес уже ведут; либо план stale **> 7** дней |
| Карта F0 | у активного нет полной карты (рост, исходный вес, пол, дата) — как минимум для старта тренировки |
| Обмеры F2 | нет замера за период, если цель на тело **или** обмеры уже вели |
| Настройки клуба | **Структура → Качество ведения**: веса осей (сумма 100%); внутри **Ведения** и **Хвостов** — доли пунктов (сумма 100% по включённым); **Глубина** — один пункт = весь вес оси; потолок 79 — тумблер без доли |
| Тонкая тренировка | 1 упражнение с данными **или** ≤2 set-строк |
| Неактивные | 0–7 коридор · 8–14 внимание · **>14** stuck (без архива) |
| После БЗ | то же; исход: ДК / отказ ПНК / архив |
| Мало данных | &lt;8 completed или &lt;3 активных — care/depth не сравниваем; stuck всё равно |

Статусы: **Ок** / **Внимание** / **Разбор** / **Мало данных**.  
`stuck ≥ 1` → не «Ок» (обычно «Разбор»).

## Где в UI

- Админ: **Статистика клуба** → карточка **«Качество ведения»** (средний балл /100) → по клику таблица по тренерам. В рейтинге по завершённым — чип статуса и балл.
- Админ: **Структура → Качество ведения** — веса осей, доли внутри ведения/хвостов и тумблеры (сохраняется на клуб).
- Тренер: **Статистика** → та же карточка (свой балл) → по клику своя строка и факты.
- В фактах имя клиента — ссылка на карточку (`/admin/clients/:id` или `/trainer/clients/:id`).
- `averageScorePct` — среднее по тренерам с баллом (без «нет балла»).

## Проверка

```bash
node scripts/verify-coach-quality.mjs
```

Входит в `npm run qa:local` через `agent-qa.mjs`.

Набор покрывает:

| Блок | Что проверяет |
|------|----------------|
| **TECH** | тонкая/глубокая запись, F1/F2, коридор неактивных 0–7 / 8–14 / >14, БЗ/архив/won, статусы и оси просадки, индексы обмеров/веса |
| **COACH** | конвейер тонких, stale-рацион, обмеры только где уместно, хвост→архив, хвост после БЗ, мало данных без ложного минуса за списание |
| **MANAGER** | два тренера (объём vs качество), сортировка «разбор» сверху, фильтр одного тренера, медиана клуба, равный объём разное ведение, доли внутри осей |

Ручной смоук: статистика админа и тренера → блок «Качество ведения» → просадка + факт → ссылка на клиента.

## Не в этом MVP

- Минус за отсутствие записи звонка (outreach).
- Привязка к ЗП / публичный рейтинг.
- ИСКРА как часть индекса.
- % оформлений ПНК внутри care (продажи — отдельный контур).
