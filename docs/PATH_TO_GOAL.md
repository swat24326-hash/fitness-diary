## 2. Сквозной путь (одна правда)

Идеал конечной цели (логика CRM, не жёсткий порядок часов в зале):

```text
Заявка/лид → визит (ПНК) → клиент + абон ↔ оплата
        → тренировки/зал → продление / закрытие → задание / outreach → отток или повтор
```

Оплата **связана** с клиентом/абоном/продажей (часто в момент продажи), а не «после всех тренировок».

| Этап | Сейчас | Разрыв к цели | Следующий кусок |
|------|--------|---------------|-----------------|
| Заявка с сайта | ⏸ нет | Вход с улицы не в CRM | L2 сайт → ПНК (не вместо L3, если деньги — главная боль) |
| ПНК / визит | ✅ | Углублять, не плодить второй CRM | Швы, качество визита |
| Клиент + абон | ✅ | Держать | Не ломать sync |
| Тренировки / офлайн | ✅ | Держать | Стабильность, качество ведения |
| **Оплата** | 📋 мост Excel/1С | Главный разрыв операционки | **После переезда (R3+):** домен `payment` → касса |
| Продажи / план / стратегия | ✅ (часть из файла) | Сводка без ledger | После payment — день из строк |
| Продление / outreach / планёрка | ✅ | Шов «стратегия → задание» | STRATEGY §5.8 P1 (после РФ или по команде) |
| **Call-центр** | ✅ канал + журнал + история в карточке | Очереди из CRM, роли, сценарии | [PRODUCT_VISION.md](./PRODUCT_VISION.md) §2.4; [OUTREACH_CHANNELS_ROADMAP.md](./OUTREACH_CHANNELS_ROADMAP.md) |
| Управление / бриф | роль ✅; единый бриф ⏸ | Один утренний экран | §5.8 P2; [CLUB_SUPERVISOR.md](./CLUB_SUPERVISOR.md) |
| ИСКРА | ✅ | Сильнее на единой правде оплат | Не вместо домена платежа |
| Сеть / РФ-данные | R2 волна 2 ✅ (2026-09-29) | C2 на стенде; R3 на **`app-core.ru`** | [PRE_R3_OWNER.md](./PRE_R3_OWNER.md), [R3_DOMAIN.md](./R3_DOMAIN.md); пилот по команде |

**Правило нарезки:** чиним **разрыв на пути**, а не самый красивый экран рядом. **Оплаты и касса — после стабильного переезда на РФ** (решение владельца 2026-08-08): до R3+ Excel/1С-импорт остаётся **осознанным мостом**; не начинать домен `payment` / кассу «заодно» с R1–R3. Иные фичи «ещё отчёт из файла» до L3 — только с пометкой **мост**, без цементирования вечной архитектуры.

**Параллельность:** #1 всегда; фокус сейчас — #2, затем #3. Ёмкость (#1c) — по сигналам, не отдельным фронтом. Продуктовые ставки #4–9 — по одной, после #2–3. **Касса (#10)** — через ворота «работает идеально», за ней только #11.

**Запрос «давай платежи/кассу сейчас»:** напомнить решение — платёж после #2–3, касса последней через ворота [RELIABILITY_PLAN.md](./RELIABILITY_PLAN.md); предложить мост (Excel) или сдвиг только **явной** командой владельца.

**Конфликт правил:** stability → фазы РФ (STRATEGY) → эта очередь. Цель не отменяет зал и cutover; L3 не обгоняет переезд.

**Запрос вне очереди:** не отвергать молча. Коротко: проекция цели + «мост / после переезда / сдвиг только явной командой». Владелец одной фразой может изменить политику.

**Что агент предлагает в конце заметного ответа:** один **следующий шаг** (из очереди или явный сдвиг владельца). До закрытия #2–3 по умолчанию **не** предлагать старт кода оплат; кассу — только после ворот «работает идеально».

## 5. Что значит «руководить процессом» — чтобы работало

Лозунг «агент ведёт» бесполезен без ритуала. Ниже — **рабочий контракт**.

### 5.1. Кто что делает

| Роль | Делает | Не делает |
|------|--------|-----------|
| **Владелец** | Цель и «да/нет» на крупные ставки; кабинеты облака; оплата; пароли; фразы-команды (`стартуем R2…`, `берём платежи`, `деплой`) | Не обязан писать микротаски и помнить все файлы |
| **Агент** | Нарезает работу; стыкует с целью и очередью §4; пишет код/docs; называет следующий шаг; эскалирует только то, что нельзя делегировать | Не меняет конечную цель молча; не стартует R2/§5.7/кассу/§5.8 без правил/команды; не ломает зал ради «красоты стека» |

### 5.2. Когда полный ритуал, когда нет

| Тип работы | Ритуал полный | Достаточно |
|------------|---------------|------------|
| Новая фича, приоритет, спор «что делать» | Да (пункты ниже) | — |
| Баг sync / абон / критический путь | Кратко: ставка #1 + fix | Не размазывать vision |
| Мелкий стиль, опечатка, узкий lint | Нет | Сделать и ship |
| Явная команда владельца (`стартуем R2`) | Коротко подтвердить фазу + чеклист | Не переубеждать без риска |

Полный ритуал (3–6 пунктов) на **заметной** задаче:

1. **Ситуация** — кому и зачем в клубе.  
2. **К цели** — шаг / мост / не наше (вердикт).  
3. **Слой** — L0–L4 или «регрессия / переезд / security».  
4. **Место в очереди §4** — почему сейчас, что откладываем.  
5. **Сделать** — конкретный следующий кусок (файл/ТЗ/verify).  
6. **Владельцу** — только если нужны кабинет, деньги, go/no-go.

Без п.2–4 на новой фиче задача «просто удобная» не должна маскироваться под движение к цели.

### 5.3. Ритуал на неделю / между чатами (когда уместно)

Агент напоминает или сам держит:

- Где мы на сквозном пути (§2) — какой **главный разрыв**.  
- Одна **ставка фокуса** из §4 (не пять параллельных «важных» *новых* фронтов; #2+#3 — допустимая пара).  
- Что **заморожено** из‑за активного R2/R3.  
- Что нужно от владельца одной фразой (если нужно).

Новый чат: PRODUCT_VISION §1–1.2 + этот файл §2–5 + handoff — не ждать пересказа цели.

### 5.4. Как выглядит управление на практике (примеры)

| Ситуация | Плохое «ведение» | Рабочее ведение |
|----------|------------------|-----------------|
| Просят «красивый дашборд» | Сразу кодить графики | «К цели слабо; лучше день из платежей / бриф P2 — или мост?» |
| Просят TS / новый стек | Большая миграция | «Средство; контракты по касанию; big-bang после РФ (§5.9)» |
| Баг sync на планшете | «Потом допилим цель» | Ставка #1: чиним зал |
| «Давай всё: касса + сайт + R2» | Параллельный фронт | Одна ставка фокуса; остальное в очередь с причиной |
| «Сделаем платежи, R2 ещё не стартовали» | Начать L3 на Vercel | **После переезда**; до R3+ — мост Excel, фокус R1/R2 |
| «Кассу заодно с R2» | Смешать cutover и кассу | Сначала стенд/пилот; касса после `payment` на РФ |
| Тишина после задачи | Ждать новое ТЗ | Сам: «Следующий шаг — … Согласны?» |

### 5.5. Definition of Done «процесс сработал»

- [ ] Решение стыковано с целью (шаг / мост / отказ) — для фич/приоритетов  
- [ ] Есть **один** названный следующий шаг  
- [ ] Не открыли запрещённую фазу (R2/§5.7/касса/§5.8) без команды/правил  
- [ ] Критический путь защищён (lint / verify / qa по ship)  
- [ ] Docs обновлены, если сменились поведение, статус или очередь

## 6. Как пользоваться

1. **Новая фича / спор** — vision (входит?) → этот файл §2–4 (разрыв и ставка) → код.  
2. **Агент в чате** — §5.2 по типу задачи; правило `fitness-diary-north-star-lead.mdc`.  
3. **Обновлять** при смене главного разрыва, завершении ставки или команде владельца сдвинуть очередь.
