# Приложение для клиентов

**Актуально:** 2026-10-02  
**Статус:** 📋 решение владельца, **код после** недели мониторинга R3 и §5.7 security ([PATH_TO_GOAL.md](./PATH_TO_GOAL.md) §4, ставка 4b).

## Ситуация

- Клиент дома хочет знать остаток абонемента и дату окончания — сейчас пишет тренеру / звонит администратору.
- Клиент хочет видеть свою следующую тренировку — она уже есть в ежедневнике тренера ([TRAINER_SCHEDULE.md](./TRAINER_SCHEDULE.md)).
- Клиент хочет видеть свой прогресс и бонусы лояльности — данные уже в Ядре ([LOYALTY.md](./LOYALTY.md)).

**К цели:** клиент видит ту же правду, что тренер и менеджер; без второй базы и без Excel. Стандартный слой сильных club-OS.

## MVP (v1) — только просмотр

Выбор владельца 2026-10-02:

| Блок | Источник |
|------|----------|
| Мой абонемент: остаток, дата окончания | абонементы клиента (`membershipRules.js`) |
| Моя следующая тренировка | ежедневник тренера |
| Мой прогресс: тренировки, веса, замеры | журнал тренировок клиента |
| Бонусы лояльности | баланс ПЗ |

**Вход:** телефон + код из SMS (канал SMS уже есть). Клиент видит **только свои** данные — проверка на сервере, не во фронте.

**Не в v1:** самозапись (v2), оплата / продление (после домена платежа, ставка #5).

## Почему после security

Сейчас входят ~36 сотрудников; клиентский вход — сотни внешних людей. До старта нужны §5.7: лимиты попыток входа / SMS, серверная изоляция «клиент → только свой `client_id`». Офлайн-sync тренера приложение не трогает (отдельный лёгкий read-only контур).

## Открытые вопросы (до плана)

- Отдельный адрес (поддомен) или раздел в том же PWA.
- Что делать с клиентом без телефона / с одним номером на нескольких клиентов.
- Какие поля прогресса показывать клиенту (не все заметки тренера — для клиента).
