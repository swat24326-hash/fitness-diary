# Приложение для клиентов

**Актуально:** 2026-10-09  
**Статус:** ✅ v1 в проде с 07.10.2026 (только просмотр; коммит `0928b34`, миграция `20261007120000_client_portal.sql` применена). Проверено на проде: QR → `/me` с данными клиента → «Выйти» гасит сессию. Ставка 4b в [PATH_TO_GOAL.md](./PATH_TO_GOAL.md) §4.

## Ситуация

- Клиент дома хочет знать остаток абонемента и дату окончания — сейчас пишет тренеру / звонит администратору.
- Клиент хочет видеть свою следующую тренировку — она уже есть в ежедневнике тренера ([TRAINER_SCHEDULE.md](./TRAINER_SCHEDULE.md)).
- Клиент хочет видеть свой прогресс и бонусы лояльности — данные уже в Ядре ([LOYALTY.md](./LOYALTY.md)).

**К цели:** клиент видит ту же правду, что тренер и менеджер; без второй базы и без Excel.

## Конечная цель — «мой клуб в кармане» (решение владельца 10.10.2026)

## Как пользоваться (зал)

1. Карточка клиента → иконка телефона «Пригласить в приложение клиента» (тренер — у своих клиентов; администратор, управляющий, менеджер — у клиентов своего клуба).
2. Клиент наводит камеру на QR-код или получает ссылку в мессенджер («Скопировать ссылку»).
3. Ссылка одноразовая и живёт 72 часа. Новая ссылка гасит прежнюю неиспользованную.
4. Телефон потерян или сменился — в той же модалке «Отключить все входы». Архив клиента закрывает доступ сразу.

Клиент открывает `app-core.ru/me` и ставит его на главный экран — значок называется **как клуб** (manifest отдаёт `/api/client-me?manifest=<клуб>`), не «Ядро» и не рабочее приложение зала. На iPhone подпись значка фиксируется при установке: переименование клуба потом её не меняет.

**Баннеры первого входа (07.10.2026):** после входа по QR / ссылке сверху `/me` по одному шагу с одной большой кнопкой: «Установите приложение клуба» (Android — системное окно, iPhone — 3 шага «Поделиться → На экран „Домой“») → «Включите напоминания о тренировках». «Позже» прячет шаг до следующего захода, после 3 раз — больше не показываем (остаётся в меню и настройках). Уже установлено / уведомления запрещены / push не настроен — шаг не показываем. iPhone в Safari видит только установку: напоминания включаются уже в приложении со значка. Правила — `src/lib/client/clientOnboardingCore.js`, проверка `scripts/verify-client-onboarding.mjs`.

**Вход значка на iPhone:** у значка «Домой» своё хранилище — сессия из Safari туда не переходит. Пока в Safari показан баннер установки, страница берёт одноразовое приглашение на 2 часа (`POST /api/client-me {action:'handoff'}`, `created_by = null`) и кладёт его в адрес `/me?h=…` и в `start_url` manifest. Баннер скрыт («Позже», следующий шаг) — токен убирается из адреса и manifest: скопированная из Safari ссылка не впускает чужого. Журналы сервера токен не пишут (Caddy без access log, API логирует только путь) — закреплено в verify. Значок при первом запуске гасит приглашение через `/me/join` — клиент сразу внутри. Новый handoff гасит прежний handoff, ссылку из клуба не трогает. Код — `clientHandoffCore.js` (сервер и `src/lib/client/`), `useClientHandoff.js`; проверка `scripts/verify-client-handoff.mjs`. **iPhone и manifest (с 10.10, INC-2026-10-10-01):** iPhone запоминает manifest с загрузки страницы и не видит подмену из React. Поэтому на `/me` manifest зала не ставится вовсе (`public/manifest-boot.js` — только вне `/me`), а на iPhone `/me` не добавляет и manifest клуба: значок берёт текущий адрес `/me?h=…`, название — `apple-mobile-web-app-title`. Android — manifest клуба из `useClientBranding`. Проверка `scripts/verify-pwa-single-manifest.mjs`; живой iPhone — после выкатки.

**Меню (бургер в шапке, на всех экранах):** выпадающее как у тренера (те же классы `app-header__*`): имя клиента → раздел «Настройки» (`/me/settings`, переключатель «Напоминания о тренировках») → «Установить на телефон» (если ещё не установлено — открывает баннер установки) → «Выйти». Новый раздел — ещё один `NavLink` в `src/pages/client/ClientMenu.jsx`.

В шапке — название клуба, внизу мелко «работает на Ядре».

**Подача (этап 1, 07.10.2026, только экран):** первым — «Мой прогресс» (решение владельца): маленькие виджеты в один ряд — «всего», «за 30 дней», последняя тренировка («сегодня» / «вчера» / «11 дней назад»), изменение веса («−5 кг / с 01.06.26»: знак мельче и тоньше цифры; с годом, клиент может ходить несколько лет; только если замеров ≥2); ниже график веса (`ClientWeightSpark.jsx`, стили `src/styles/client-me-spark.css`): в шапке крупно текущий вес и «дата · последний замер»; плавная кривая (монотонный сплайн — не рисует вес выше максимума и ниже минимума) с градиентной заливкой, справа подписи макс/мин; при появлении линия прорисовывается слева направо, точки всплывают по очереди, у последнего замера мягкий пульс. По кнопке «Обновить» график оседает к низу (не меньше 0,42 с) и, когда пришли свежие данные, пружинисто собирается заново (`useSparkRebuild.js`); первый заход и фоновые загрузки так не анимируются. Тап или ведение пальцем — шапка показывает выбранный замер и «с тех пор −5 кг»; на ПК — наведение и стрелки. Одна точка — просто «Вес: X кг». Логика — `weightSparkPath`, `nearestDotIndex`, `weightSparkCaption` в `clientMeHighlightsCore.js`; `prefers-reduced-motion` отключает анимации. Под ним абонемент и следующая тренировка — квадратными плитками в один ряд, одна схема для симметрии: заголовок → крупное значение («44 из 50» / «18:00», растёт с плиткой) → подпись («тренировки осталось» / «завтра») → подвал на одной линии (полоска + «До 27.01.2027» / «Тренер: Анна»). Нет данных — прочерк в обеих. Тренировка сегодня/завтра — левая, иначе слева абонемент. Подсказка о продлении и уже купленный следующий абонемент — заметкой под плитками. Правила — `src/lib/client/clientMeTilesCore.js`. Подсказка «продлить можно у администратора клуба» — когда осталось ≤2 тренировок или ≤7 дней; молчит, если следующий абонемент уже куплен или текущий исчерпан (там уже есть подпись). Вес — мини-график по датам: точка на каждый замер, слева подписи макс / мин кг (резкий замер виден как точка, а не как сбой линии). Полоска абонемента заполняется по остатку — как цифра «осталось N из M». Правила — `src/lib/client/clientMeHighlightsCore.js`, проверка `scripts/verify-client-me-highlights.mjs`.

## Безопасность

- Доступ решает сервер: `requireClientUser` принимает только токен клиента (`typ: client`), сверяет сессию и архив на каждый запрос, отдаёт строки только этого `client_id`.
- Токены клиента и сотрудника не взаимозаменяемы (проверено в `scripts/verify-client-auth.mjs`).
- Ответ `/api/client-me` — белые списки полей (`scripts/verify-client-me-whitelist.mjs`): без заметок тренера, `data` тренировок, оплат, телефонов, id сотрудников.
- Push-подписки и журнал напоминаний — только сервер (RLS без политик); клиент видит и удаляет только свою подписку.
- Код: `api/_lib/clientPortal/`, контракт — [API.md](./API.md), таблицы — [DATA_MODEL.md](./DATA_MODEL.md).

На iPhone push приходит только приложению со значка «Домой» (iOS 16.4+): в Safari вместо переключателя подсказка «сначала установите». Запрещено в настройках телефона — подсказка, как разрешить. Клик по уведомлению открывает `/me`.

**Как устроено:**

- Подписка — `client_push_subscriptions`, привязана к **сессии** клиента: «Выйти», «Отключить все входы» и архив гасят напоминания сразу, без отдельной отписки. Телефон = один клиент (endpoint уникален). Endpoint принимаем только от известных push-служб — POST на него делает наш сервер.
- Отправка — `scripts/client-reminders-vm.mjs` по cron на ВМ каждые 15 минут. Шлёт только в 19:00–22:00 по часам клуба (опоздавший cron догоняет, после 22:00 — тихие часы до 9:00, не шлём). Берёт слоты ежедневника на завтра, где клиент в `client_ids`.
- Без дублей — журнал `client_reminder_log` (клиент + день + время слота): слот сначала занимаем, потом шлём. Не дошло ни на один телефон — слот освобождаем, следующий запуск повторит. Ответ 404/410 — подписку удаляем.
- Текст: заголовок — название клуба, тело — «Завтра в 18:00 — тренировка с Анной». Имя тренера склоняем только для понятных русских имён, иначе «тренировка, тренер Ким». Заметка слота не уходит.
- Ключи VAPID те же, что у сотрудников (`webPushCore.js`, [PUSH_SETUP.md](./PUSH_SETUP.md)); service worker общий (`public/push-sw.js`), поэтому при выключении снимаем только запись на сервере, не подписку браузера.
- Код: `api/_lib/clientPortal/clientReminderCore.js` (правила), `clientReminderJob.js` (отправка), `clientPushHandler.js` (API); экран — `src/pages/client/ClientSettingsPage.jsx`, `ClientOnboardingBanner.jsx`, `useClientPush.js` (общий через `ClientAppContext.jsx`). Проверка — `scripts/verify-client-reminders.mjs`.

**Выкатка (один раз):** миграция `20261007190000_client_push.sql` (`scripts/r2-pg-migrate-vm.sh`) → деплой → на ВМ `sudo bash scripts/client-reminders-install-vm.sh` (ставит cron и делает пробный `--dry-run`: сколько напоминаний ушло бы сейчас). ## ДЗ и питание от тренера (📋 ТЗ, решения владельца 10.10.2026)

**Ситуация:** тренер отправляет ДЗ и рацион картинкой в личный мессенджер — картинка тонет в переписке, клуб её не видит, при смене тренера теряется. Клиент вечером дома не помнит, что задано; в магазине без сети хочет посмотреть ужин по плану.

**Решения:** отдельно от «Сообщений» — плитки на главной `/me`; клиенту видно последнее на плитке + список прошлых внутри; отправляют тренер клиента и главный админ; отправка с планшета работает без сети (очередь sync); делать **после выкатки переписки** ([CHAT.md](./CHAT.md)), чтобы не смешивать две миграции в одной выкатке.

**MVP:**

- **Клиент:** второй ряд плиток под абонементом / тренировкой (та же схема): «Домашнее задание» — «6 упражнений · от 08.10 · Анна», «Питание» — «1850 ккал · Б/Ж/У · от 05.10». Точка «Новое», пока не открыл. Нет ни того, ни другого — ряд скрыт; есть одно — вторая плитка с прочерком. Нажатие → `/me/homework`, `/me/nutrition`: только просмотр, вид как на PNG, без заметок тренера и опросника здоровья; без сети — из последней загрузки.
- **Тренер:** кнопка «В приложение» рядом с «В Max» на экранах ДЗ и рациона. Устаревший рацион (`nutritionPlanStaleCore.js`) не отправляется — «Сначала пересоберите». После отправки — «Отправлено 10.10, 18:40», после открытия клиентом — «Просмотрено».
- **Push клиенту:** «Анна прислала домашнее задание», тихие часы 22:00–9:00; шлёт задача на ВМ по cron (как напоминания), отправка тренера от push не зависит.

**Как устроено (план):** таблица `client_plans` — снимок отправленного (`client_id`, `club_id`, `kind` homework | nutrition, `payload`, `sent_by`, `sent_at`, `client_seen_at`, `notified_at`), RLS без политик. Рацион клиенту не отдаём из `health_cards` (там здоровье и опросник). Запись — `saveLocalWithSync` → allowlist push + ветка `authorizePush` (тренер — только свой клиент, главный админ — любой). Клиент — `/api/client-me`: сводка для плиток в GET, полный снимок по нажатию; новых `api/*.js` нет. Код — `api/_lib/clientPlans/`, `src/lib/client/clientPlanTilesCore.js`, `homework/homeworkAppSendCore.js`, `nutrition/nutritionAppSendCore.js`. Проверка — `scripts/verify-client-plans.mjs` (белый список, чужой тренер — отказ, устаревший рацион, «новое», тихие часы) + сценарий в `qa:screens`; критический путь sync → `qa:local`. Правило `fitness-diary-client-plans.mdc` поправить: ДЗ-черновик по-прежнему не в `health_cards`, но отправленный снимок хранится.

**Потом (не в MVP):** «Сделал» у ДЗ → тренер видит регулярность; ИСКРА утром «5 клиентов не открывали ДЗ неделю»; «съел по плану» у приёма пищи.
