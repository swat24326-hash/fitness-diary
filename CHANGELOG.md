## 2026-08

- **Продажи / главная менеджера:** убраны 403 на план ЗП и кабинеты тренеров — менеджер (и управляющий) может **читать** настройки своего клуба для прогноза на главной; менять по-прежнему только админ.
- **Клиенты / звонок клуба:** ✅ в проде — на доске **Позвонить**; общий журнал; исход webhook; **плеер записи** в строке (+ «Скачать»). Docs: [MOIZVONKI_SETUP.md](./docs/MOIZVONKI_SETUP.md).
- **Продажи / статистика менеджера:** в «Тренировки по типам карт» снова **ФИО** сотрудников (не UUID) — имена дотягиваются и для неактивных / другого клуба в матрице месяца. Docs: [SALES_MANAGER.md](./docs/SALES_MANAGER.md).
- **Безопасность / Sync:** admin на API только по роли (убран хардкод email); push update абона/тренировки/медкарты проверяет владельца существующей строки; pending ПНК и клипов не затираются pull; списание абона после сохранения completed. Verify: `verify-security-l1-audit.mjs`.
- **Документация:** системная карта приведена к коду — деплой через `/api/*` (не Edge), handoff IDB 16 + multi-hall + supervisor, DATA_MODEL без фейковых IDB stores ЗП/CQ, роли в API/SYNC, статусы управляющего. Карта: [docs/README.md](./docs/README.md).
- **Клиенты / карточка админа:** телефон, № карты и ФИО больше не откатываются при обновлении данных (та же защита, что у даты рождения). В списке «Тренер ПЗ» по сети — нормальные названия клубов, не обрезки UUID. При смене клуба вместе с картой проверяется новый №; абоны и тренировки получают новый `club_id`; после неудачной отправки в облако карточка не перезатирается старыми данными с сервера.
- **Тренер / срок абона:** если абон уже стартовал, но клиент впервые пришёл позже (в пределах 14 дней) и занятий ещё не было (учёт + дневник) — экран «Сдвинуть и начать»; можно «без сдвига». При пересечении со следующим абоном или опоздании >14 — баннер, тренировка доступна. Сдвиг также на черновике и перед «Завершить»; даты обновляются на вкладке абонов/карточке. Verify: `verify-membership-early-activate.mjs`.
- **Клиенты / массовые SMS:** админ, менеджер и управляющий — фильтр → галочки → один текст → код подтверждения (как при удалении) → очередь через Мои Звонки (пауза под 20/мин). После пачки — итог «ушло / ошибки»; в журнале SMS видны и успехи, и сбои. Docs: [MOIZVONKI_SETUP.md](./docs/MOIZVONKI_SETUP.md), [OUTREACH_CHANNELS_ROADMAP.md](./docs/OUTREACH_CHANNELS_ROADMAP.md).
- **Тренировка / пульс:** удаление черновика при включённом пульсометре больше не оставляет хвост сэмплов этой тренировки; датчик в шапке остаётся подключённым. Docs: [TRAINING_HR.md](./docs/TRAINING_HR.md).
- **Клиенты / ДР сегодня:** на плитке только кто празднует **сегодня** (иначе 0); по клику — список сегодня + ближайшие 30 дней.
- **Клиенты / абон 0/0:** авто-пакет без занятий остаётся в «Не активных», но подпись больше не «лимит исчерпан» — а **«нет занятий в пакете»** (это не израсходованные тренировки).
- **Клиенты тренера:** чипы = список; ДР — цифра «сегодня», список по клику = окно. Verify: `verify-trainer-clients-browse-filters.mjs`.
- **Клиенты / плитки:** единый слой `adminClientsBrowseFilterCore` — chip = list; АЗ-направление в counts; поиск по клубу сбрасывает воронку; «Все (без ПНК)». Verify: `verify-admin-client-quick-filters.mjs`.
- **Статистика (админ и тренер):** убрали дубль «Всего / Действующих / Не активные» — смотрите фильтры в «Клиентах»; на статистике остаются тренировки, типы, ПНК, качество. Сводка дня / сигналы для «Не активные» ведут в Клиенты (финал воронки). Docs: [CLIENT_MULTI_HALL.md](./docs/CLIENT_MULTI_HALL.md).
- **Статистика клуба:** вкладки **ПЗ | ТЗ | АЗ** — типы карт по залу; ПНК, тренировки, рейтинг и качество — только на ПЗ. На ПЗ в API «Всего» не попадают люди только с абоном ТЗ/АЗ. Docs: [CLIENT_MULTI_HALL.md](./docs/CLIENT_MULTI_HALL.md).
- **Продажи / Прайс ТЗ и АЗ:** полное редактирование как у ПЗ, под каждое направление — типовая сетка без Excel, строки/направления, часы ТЗ, автосвязь полной и −10% у АЗ. Docs: [PRICE_LIST.md](./docs/PRICE_LIST.md).
- **Клиенты / «Все клиенты»:** цифра на плитке = клиенты **текущей вкладки** (как в списке), без подмены клубным census из Статистики. Docs: [CLIENT_MULTI_HALL.md](./docs/CLIENT_MULTI_HALL.md).
- **Продажи / полоска плана:** маркеры уровней 1/2/3 больше не склеиваются, если суммы планов почти одинаковые.
- **Финансы:** плитку/строку «Заработок» убрали с экрана — для управления хватает чистой (выручка − возвраты − ЗП − расход); промежуточный «заработок минус только возвраты» путал.
- **Финансы / прогноз ЗП ПЗ:** оранжевый прогноз «ЗП персонального зала» (и чистая) считает уровни плана к концу месяца и надбавки кабинета, а не только «средняя ₽ × часы». Без разбивки по тренерам — прежний темп.
- **Продажи / ЗП дня:** в матрице тренировок колонки **База** и **Итого ЗП** по тренерам (ставки ур. 1–3, кабинет «с планом / без», надбавка ±₽). Без плана — факт ур. 3 и сценарии 1/2/3 под базой. В статистике «по типам карт» — тот же контур + линейный прогноз уровня до конца периода. Дни только «По клубу» не двигают MTD тренера; сумма дней ≠ месяц по финальному уровню (так задумано).
- **Тренер / ранняя активация:** кнопка «Новая тренировка» в списке и карточке больше не режет алертом клиентов с абоном «начнётся …» — открывается экран подтверждения сдвига дат.
- **Продажи / карточки из оплат:** если оплата по карте человека **из архива** — предлагаем «Вернуть из архива» (и абон при необходимости), а не создавать нового клиента. Если по № карты в клубе уже несколько клиентов — больше не предлагаем «Создать» (это плодило дубли). Строка уходит в «Дубли карты» со ссылкой в Клиенты; по возможности матч сужается по ФИО из файла. Если менеджер уже завёл карточку/абон днём — вечерний разбор сначала тянет клиентов из облака и не предлагает создать зал, который уже есть на карточке.
- **Клиенты / тренер ПЗ:** смена тренера только в карточке (поле «Тренер ПЗ»); из меню ⋮ пункта убрали. У админа сети — тренеры всех клубов, при смене клуба спрашиваем подтверждение.
- **Клиенты / карточка админа:** на вкладке **ПЗ** снова те же разделы, что у тренера (здоровье, питание, ДЗ, абоны, тренировки, статистика); переключатель ПЗ/ТЗ/АЗ сверху сохранён. В поиске стек залов больше не ломает сетку строки.
- **Клиенты / оплата на абоне ПЗ:** админ и менеджер на карточке видят и правят **цену пакета** (₽) у абона ПЗ — как на ТЗ/lite. Это не касса и не журнал платежей (они после РФ).
- **Клиенты / поиск:** поиск по ФИО, карте или телефону идёт по **всем залам** (не зависит от вкладки ПЗ/ТЗ/АЗ); в выдаче блоки залов друг под другом. Docs: [CLIENT_MULTI_HALL.md](./docs/CLIENT_MULTI_HALL.md).
- **Клиенты / одна карточка:** у админа, менеджера и управляющего на карточке всегда переключатель **ПЗ / ТЗ / АЗ** — абоны разных залов на одном человеке, без трёх разных клиентов. Можно назначить тренера ПЗ. Docs: [CLIENT_MULTI_HALL.md](./docs/CLIENT_MULTI_HALL.md).
- **Отчёт продаж / Excel часов ПЗ:** колонка **СОТ** (кириллица) снова находится тип **COT** (латиница) — одинаковые на вид буквы больше не ломают подстановку.
- **Типы абон.:** название типа можно до **40** символов (было 12) — длинные имена АЗ/ПЗ вроде «Воздушная растяжка».
- **Типы абон. / ПЗ:** галочка **«В план»** — какие карты закрывают пороги плана ЗП (независимо от ставок ₽). Миграция `counts_toward_pay_plan`.
- **План ЗП:** в пороги уровней идут типы с галочкой «В план»; без флага в старом кэше — фолбэк «ставка > 0 ₽».
- **Продажи / план и прогноз:** факт и прогноз по направлениям = карточкам клуба; в таблице — доп. продажи, «Неразнесено» при дыре плана, строка Итого; «До плана напр.» в строках ≠ дыра клуба.
- **R2 prep:** portable host с `/api/health`, Docker build-args `VITE_*`, `db:migrate:pg` со stub `auth.*` для голого Postgres. День 1 стенда = hybrid (хост на РФ, данные пока Supabase). Docs: [R2_C2_STAGING_RUNBOOK.md](./docs/R2_C2_STAGING_RUNBOOK.md).
- **Типы абон.:** можно переименовать карту (ПЗ и АЗ) карандашом в «Структура → Типы абон.» — меняется только название; уже выданные абонементы не отвязываются.
- **ПНК / итог визита:** на доске «Тренировка» опирается на число завершённых БЗ с сервера (как у тренера), а не только на отметку в воронке.
- **Sync / менеджер:** ошибочная правка медкарты/веса больше не крутит очередь на HTTP 403 («только клиенты и абонементы») — запись снимается; вкладка здоровья у менеджера — только просмотр. Docs: [SYNC.md](./docs/SYNC.md), [SALES_MANAGER.md](./docs/SALES_MANAGER.md).
- **ПНК / glance ×10:** сеть на главной не чаще 25 с; после «Обновить» на доске — event в кэш без второго refetch. Правда цифр сохраняется, нагрузка под активную админку и много клубов.
- **Клиенты / ДР:** цифра на плитке — по-прежнему «сегодня». По клику — сегодня и ближайшие 30 дней; список разделён на блоки «Сегодня» и «Ближайшие». SMS/Max-поздравление только у кого ДР сегодня.
- **ПНК / доска:** больше не открывается сразу на «Внимание» — по умолчанию «Все», иначе тихие на «Оформлении» пропадали с доски при живой карточке на главной.
- **ПНК / главная vs доска:** карточка больше не «висит» на главной после ухода из работы — glance всегда перепроверяет список; «Обновить» на доске сразу пишет ту же правду в кэш главной. После бесплатной тренировки «Начало тренировки» не остаётся серым без `visit_started`.
- **ЗП / заморозка месяца:** прошлый календарный месяц считает ЗП по снимку ставок/плана/кабинетов (не по текущим настройкам). Текущий месяц — live. Матрицу в прошлом править можно — пересчёт по замороженным правилам. Миграция `club_trainer_pay_month_snapshots`.
- **Структура / Тренеры / Кабинет:** «с планом» / «без плана» + ±₽ за тренировку; на карты с оплатой **0 ₽** надбавка/минус не действует. ЗП считает уровни и adj. Миграция `trainer_pay_profiles`.
- **Структура / План ЗП:** вкладка с порогами **тренировок** месяца (целые; стандарт 80 / 120). Полосы без дробей (101 / 141 → 0–100 / 101–140 / от 141). Ставки ₽ — в «Типы абон.»; кабинет — в «Тренеры». Миграция `club_trainer_pay_plan_settings`.
- **Типы абон. / ПЗ:** у каждого типа карты три ставки оплаты тренеру (ур. 1–3). В ЗП берётся нужный уровень по плану клуба и кабинету тренера. Нужна миграция `20260808120000_membership_types_trainer_pay_tiers.sql` на Supabase.
- **Главная админа:** «Качество ведения» — полный glance в ряду внимания; в сводке дня только тихая цифра. Ряд внимания на широком экране всегда 3 колонки — план не прыгает при появлении ПНК.
- **«Не активные» / плитка:** цифра на чипе совпадает со списком (финал воронки). Раньше на ПЗ подставлялся широкий census «без абона» (4), а список уже был узкий (1).
- **«Не активные»:** финал воронки абона — после «Давно не был» (>60 дн.) или странный/пустой абон; больше не дублирует «Закончился» и «Давно». ПНК и «ждёт старт» вне. Статистика периода («не активные» за месяц) — по-прежнему широкий census.
- **«Закончился» / ПНК:** открытые карточки воронки ПНК больше не попадают в «Закончился» / «Истекает» / «Давно» — пробный лимит 1–2 остаётся в чипе «ПНК», не в продлении ДК.
- **«Закончился»:** не только дата конца (0–13 дн.), но и **исчерпанный лимит тренировок при ещё живом сроке** — горячее продление, не только «Не активные». ТЗ без лимита занятий (`total = 0`) не затрагивается.
- **Истекает абонемент:** окно предупреждения **1–5 дней** (было 1–3) — тренер, админ, ТЗ-календарь, SMS-отметка. Константа `MEMBERSHIP_EXPIRING_WITHIN_DAYS`.
- **Тренер / Не активные:** плитка на главной и чип в Клиентах → список `/trainer/clients?filter=inactive` (не через Профиль). Учёт: без действующего абона и не «ждёт старт»; «Давно» (14–60 дн.) по-прежнему отдельный холодный возврат.
- **Главная тренера:** «Клиенты / Профиль» ~×1,5 от плиток внимания; доска влезает в экран планшета. Если сверху появляются ПНК / задание / Sync — доска сама уплотняется, середина может чуть скроллиться.
- **Главная тренера:** заявки на абон, качество ведения и плитки клиентов (ПНК, ДР, абоны) — в одной полосе «Сегодня внимание»: слева операции, справа фильтры.
- **Дневник / просмотр:** окно «глаз» открывается поверх всего экрана (как списание абонемента), а не внутри рамки списка.
- **Клиенты / № карты:** уникальность **в клубе** (не в сети) при создании, правке, клипе, переносе в другой клуб; архив тоже держит номер. Тот же номер в другом клубе — можно. Найденный ТЗ/АЗ в Excel закрытий — новый абон не дублируется. Docs: [PZ_CLIENTS_ONBOARD.md](./docs/PZ_CLIENTS_ONBOARD.md).
- **Тренировка / пульс:** на «Итоге» без подключённого датчика блок больше не показывается — буфер сэмплов привязан к конкретной тренировке (не ко всему клиенту). Docs: [TRAINING_HR.md](./docs/TRAINING_HR.md).
- **Дневник / просмотр:** сводка пульса (ср./мин/макс, зоны, ккал) в окне «глаз»; карточка показывает ср. BPM; просмотр удобнее читать на планшете. Docs: [TRAINING_HR.md](./docs/TRAINING_HR.md).
- **Тренировка / пульс:** на новой тренировке больше не всплывает сводка пульса от прошлой сессии и «тысячи минут» — буфер сэмплов сбрасывается при старте и после «Закончить»; длительность считается в окне 4 ч. Docs: [TRAINING_HR.md](./docs/TRAINING_HR.md).
- **Продажи / Акции:** направления (ПЗ/ТЗ/АЗ/доп.) и НК/ДК/УК выбираются вместе, **одна общая цель** и одно «продано» — без разбиения по сегментам.
- **Продажи / матрица ПЗ:** вместо UUID снова показываются **ФИО** тренеров (подтягиваются из справочника после Excel/сохранения).
- **Продажи / матрица ПЗ:** уже таблица — скрыты пустые типы и нулевые тренеры (из Excel); закреплена колонка имён; нули без «коробок», цифры заметнее. Кнопка «Пустые типы» вернёт скрытое.
- **Продажи / Акции за день:** список акций — в **две колонки** (на узком экране одна), без пустой полосы между названием и полем.
- **Продажи / Excel часов ПЗ:** «Подставить» снова заполняет матрицу и сохраняется, даже если список тренеров на экране ещё пуст (раньше тост был, а таблица и сохранение — нули).
- **Продажи / Excel:** у загруженного файла — кнопка **«Отмена»** (сбрасывает превью; уже подставленную форму/матрицу не откатывает).
- **Продажи / Excel:** если тренера «нет» — пишем «нет в базе данных» (не «в Оси»). Часы ПЗ: если список тренеров ещё не подгрузился — подтягиваем его при выборе файла.
- **Продажи / Excel часов ПЗ:** имена из 1С («Фамилия Имя») снова находятся при порядке «Имя Фамилия» в карточке тренера.
- **Структура / Тренеры:** пароль, блок и удаление — в меню «⋯» в строке (как у клиентов); снаружи остаются ФИО и ИСКРА.
- **Структура / Тренеры:** можно изменить ФИО тренера (карандаш в действиях) — логин и пароль не трогаются; на планшете имя обновится после Sync или повторного входа.
- **Продажи / акции:** в плане месяца — цели со сроками; в дне — сколько продано по акции; в статистике — сводка «заложено / продано». Не ломает старые отчёты и таблицу темпа по сегментам. Docs: [SALES_MANAGER.md](./docs/SALES_MANAGER.md).
- **ПНК / доска:** плитки больше не квадратные с обрезкой — шкала шагов и низ карточки видны целиком.
